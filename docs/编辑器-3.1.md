# Impor Code Studio 3.1

> 版本：3.1.0 · 2026-11-13

本版在 3.0 的项目质量入口、教学入口与插件写权限之上，完成五项编辑器升级：全项目搜索与事务化批量替换、大文件虚拟滚动、项目依赖图与离线审计、Windows 屏幕阅读器语义桥接、设置同步与插件独立进程隔离。已有的项目索引、符号跳转、调用层级、重命名、提取函数、DAP、测试浏览器、多光标、折叠与 diff 全部保留。

## 全项目搜索与批量替换

命令面板「全项目搜索与替换（预览/事务）」或 `Ctrl+Shift+H` 打开面板：

- 支持正则、区分大小写、全词匹配。全词匹配使用 Unicode 标识符边界，`Foo` 不会命中 `foobar`，也不会因 `\b` 对中文失效。
- 按后缀扫描，结果按文件分组；每个文件可单独勾选，预览为 unified diff。
- 「只替换勾选文件」在写入前建立 `.impor_recovery/search_replace/<事务号>/`，含备份与 `manifest.json`；任一文件失败会按 manifest 反向回滚。
- 撤销按钮还原整个事务，并刷新已打开且未脏的编辑器；虚拟滚动 pane 不参与整文件重载，避免把当前窗口写成全文。
- 已知 BUG 已修复：忽略大小写/全词模式下替换串复用同一正则，且用函数返回字面替换，避免把 `\1` 当反向引用；搜索完成时先勾选可读非脏文件，再按实际变化收敛，避免“一个文件都没勾选”；窗口级搜索→替换→撤销已在真实 Tk 主循环中跑通。

纯逻辑在 `impor/editor_search.py`，UI 在 `impor/editor_search_ui.py`。

## 大文件虚拟滚动

`impor/editor_virtual.py` 的 `VirtualLargeFilePane` 继承 `EditorPane`：

- 内存保留完整行列表，Tk Text 只装入当前 3,000 行窗口；滚动超过 12% / 88% 时换块。
- breadcrumb 持续显示「虚拟滚动 起-止 / 总行数 · 只读」，启动后不会被编辑器延迟初始化覆盖。
- 行号显示绝对行号，不在窗口内重建全文。
- 默认只读；点击 breadcrumb 可转完整编辑（整文件读入，超大文件仍可能卡顿）。
- 打开超过 `large_file_kb`（默认 2,000 KB）的文件时三选一：虚拟只读 / 完整编辑 / 取消。
- 虚拟只读 pane 的保存会被拒绝并提示；`goto_line` 走 `goto_virtual_line`。

## 项目依赖图与离线审计

`impor/editor_graph.py` + `impor/editor_graph_ui.py`：

- 文件依赖图解析 `import` / `from`，支持点号模块到 `.impor` 文件、包入口 `__pkg__.impor`、唯一 basename 回退。
- 文件图扫描当前打开的工作区（不是安装根）；刷新带代次校验，快速连点不会重复插入旧结果。
- 检测循环依赖、未解析导入、自导入、孤立文件、重复模块名。
- 包依赖图复用 `pkgmgr.dependency_graph`，审计复用 `pkgmgr.audit`。
- 三标签页「文件依赖 / 包依赖 / 审计」，双击节点打开文件，可导出 JSON。
- 命令面板「项目依赖图」「项目依赖与离线审计」。

## 屏幕阅读器与键盘

- `impor/editor_uia.py` 生成当前文件、光标行列、选区、诊断、当前行、可见文本、只读/大文件状态的语义 JSON，写到 `.impor_recovery/accessibility.json`。
- `UIABridge` 在 Tk 窗口内嵌原生 Win32 `EDIT` 控件（系统自带 UIA/MSAA provider），每 900ms 刷新；原生控件失败时回退到 Tk 文本。
- `Ctrl+Alt+A` 或设置中的「启动时打开屏幕阅读器桥接」打开。
- 边界：Tk 8.6 自绘 Canvas/Text 没有自定义 UIA provider；可访问的是“语义桥接窗口 + 快捷键路径”，不是每个自绘像素。第三方 `uiautomation`、`pywinauto`、`comtypes` 在当前环境未安装，因此使用 ctypes 原生控件而非第三方库。
- 键盘路径保留 `Ctrl+1..5` 区域跳转、命令面板、字号缩放。

## 设置同步

`impor/editor_sync.py`：

- 快照 schema=1，文件名 `impor-studio-settings.json`；只导出可移植偏好（主题、字体、缩进、换行、缩略图、自动保存、格式化、大文件阈值、插件隔离、屏幕阅读器），不含 `workspace`、`recent`、`recent_commands` 等机器相关字段。
- 默认目录 `~/.impor_studio/sync`，可用 `IMPOR_SETTINGS_SYNC` 覆盖；指向 OneDrive/坚果云等云盘目录即可跨设备。
- 合并策略：`newer`（较新者优先，默认）、`local`（本地优先）、`remote`（远端优先）。
- 设置窗口提供启用开关、目录选择、策略下拉、「立即上传」「立即拉取」；保存设置时按开关自动 push。
- 启动时若启用同步且快照存在，自动 pull 后再应用主题/字体等偏好。

## 插件独立进程隔离

`impor/plugin_host.py` + `impor/studio_ext.py`：

- 默认每个插件在独立 Python 子进程中加载与执行，通过 JSON 行协议与编辑器通信；插件崩溃/死循环不再拖垮编辑器。
- 命令、格式化器、主题、状态项通过 RPC 代理；文件读写、当前文本、Toast 由父进程代理。
- 写权限仍由父进程校验：`plugin_write_allow` 或 `IMPOR_PLUGIN_PERMISSIONS`；写入路径限制在工作区内。
- 面板 builder 不跨进程执行：隔离模式下面板显示安全占位说明。需要同进程面板的插件可在文件头写 `# impor-plugin: inproc` 显式退回同进程（不推荐）。
- 设置项「插件独立进程隔离（重启生效）」可关闭。边界：这是进程隔离，不是 OS 沙箱；插件仍以当前用户身份运行，强安全边界请用受限账户/容器。

## 已知边界

- 虚拟滚动默认只读；转完整编辑会整文件读入，超大文件可能卡顿。
- 原生 EDIT 桥接只朗读语义快照，不把自绘控件逐个映射为 UIA 元素。
- 设置同步是文件级同步；同一秒内两台设备同时写同一目录时，后写覆盖先写，需靠云盘版本历史恢复。
- 插件隔离不阻止插件直接 `open()` 系统文件；写代理只约束通过 API 的写操作。
