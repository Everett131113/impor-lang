# v6.2 性能报告：函数调用与启动开销

> **历史内部性能报告，不是发布版本号。** 当前对外发布为 `3.6.6`；本文的 `v6.2` 只用于性能对照。

- 日期：2026-11-09
- 环境：Windows / Python 3.11.5 / 本机
- 目标：在 v6.1 已达成 3400 ms 门槛的基础上，继续压函数调用/递归热路径与每次启动的导入开销。

## 结果

| 指标 | v6.1 | v6.2 | 变化 |
|---|---:|---:|---:|
| `impor bench --gate` 解释器 100 万循环 | 536 ms | 520–563 ms（多次） | 约 2%–3% |
| `loop_1e6`（含进程启动） | 799.8 ms | 731.9 ms | 8.5% |
| `str_2000`（含进程启动） | 283.4 ms | 249.1 ms | 12.1% |
| `fib_22`（含进程启动） | 694.6 ms | 648.4 ms | 6.7% |
| `fib(22)` cProfile 总量 | 1.916 s | 1.758 s | 8.2% |
| `_call_closure` 自身耗时 | 0.347 s | 0.290 s | 16.4% |

> 收尾复测备注：当时系统后台负载约 41%，同机连续三次 `bench --gate` 为 958 / 1147 / 1203 ms（冷启动一次 1407 ms）。早先热机数据为 520–563 ms；两组都低于 3400 ms 门槛，差异来自机器负载，不是代码回退。

启动侧：`python -X importtime` 中 `impor.pkgmgr` 累计 95.7 ms（其中 `urllib.request` 84.5 ms、`http.client` 67.9 ms、`ssl` 11.6 ms、`zipfile` 2.7 ms）。v6.2 后 `run` 路径不再导入这些模块。

## 改了什么

1. **闭包调用信息预计算**：`Closure.__init__` 记录末行是否为隐式返回（`tail_expr`）与正文长度（`head_len`），`_call_closure` 不再每帧 `isinstance` 判断和 `body[:n_last]` 切片。
2. **参数绑定直写**：参数直接写入新环境的 `store`，不再逐个调用 `set_local`。
3. **成功路径不取异常信息**：`sys.exc_info()` 从每次调用的 `finally` 移到 `except ImporException` 分支；只有异常时才收集调用栈。
4. **包缓存目录与包管理器解耦**：`config.py` 里的 `from .pkgmgr import CACHE_DIR` 改为本地计算的 `pkg_cache_dir()`；`pkgmgr.CACHE_DIR` 复用同一个函数，路径语义不变，`run` 不再连带加载 `urllib` / `http.client` / `ssl` / `zipfile`。

## 边界

- 本轮没有改执行模型（仍是 AST 树遍历 + 局部循环专用计划），递归仍走 Python 异常做返回，和 CPython 有明显差距：`fib(22)` 约为 CPython 的 0.17x–0.21x。
- 启动导入只砍掉了包管理器这条链；Python 自身启动与核心模块导入仍在。
- 没有开启函数级 JIT/字节码，避免改变调用栈、错误信息和调试语义。

## 回归

- `fib(22)` 输出 17711。
- 闭包、隐式返回、const、字符串/数字混算、除法、负数等冒烟脚本输出与 v6.1 一致。
- `tests.test_v37.TestEnglishKeywords` + `tests.test_v43.TestKeywordCountUnchanged` 10 项通过。
- 全量 `run_tests.py` 本轮未跑完：进程在 v2.9 用例处挂起，未产出 `Ran ... tests` 汇总；已有基线偏差（10 failures / 21 errors，LSP、v2.9 旧语法、v38 自举闭包、v43 lint 等）不能据此判定本轮新增失败。已完成的冒烟与关键字回归均通过。

## 验收命令

```bat
python Impor.py bench --gate
python benchmarks\bench_compare.py
python run_tests.py
```

门槛保持 `benchmarks/gate.json` 的 `interpreter_loop_max_ms = 3400`。本轮实测 520–563 ms，仍有余量；没有借表现收紧门槛，避免慢机器/CI 误报。
