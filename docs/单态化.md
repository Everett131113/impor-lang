# 单态化（4.6.0 泛型 → 4.7.0 标注）

## 〇、4.7.0 补上的一半：按标注定型

4.6 的单态化只认**泛型**，而且必须调用点写字面量才能定型：

```impor
def max2 < T >(a : T, b : T) -> T
    ...
max2(9, 2)        // 定型成功 → gp_max2_i64
max2(x, y)        // x/y 不是字面量 → 静态类型不可知 → 回退擦除版
```

于是 `def sum_to(n: int) -> int` 这种**根本不需要泛型**的普通函数，即使在调用点传的是字面量也拿不到原生实例 —— 它不在候选里。

4.7 把 `impor/monomorph.py` 的候选池扩成两类来源：

1. **泛型**（4.6 原有）：`type_params == ["T"]`，参数标 `T`。
2. **标注**（4.7 新增）：**非泛型**函数，且**全部参数与返回**都是同一个标量标注 `int` 或 `float`。

```impor
def sum_to(n: int) -> int
    var s = 0
    var i = 0
    while i < n
        s = s + i
        i = i + 1
    return s
```

调用点判据与泛型那条一致：实参的静态类型必须与标注一致，才登记这个实例。生成：

```c
static Val gp_sum_to_i64(long long p_n) { ... }   /* 擦除版仍保留作回退 */
```

配套的 `_NativeGen` 新增 `for i in range(...)`：循环变量与累加器都用 `long long` 声明在函数开头，循环体里不出现 `Val`。`range(N)` / `range(a, b)` / `range(a, b, step)` 都支持，步长必须是字面量。

### 溢出语义：宁可慢，也不静默回绕

裸 C 的 `long long` 相加会静默 wrap，而 Impor 的对外承诺是「整数溢出报 E1012」。两者冲突，取舍是**保留检查**：

- `i64` 实例里的 `+ - *` 与 `+= -= *=` 走 `rt_ck_add` / `rt_ck_sub` / `rt_ck_mul`（入参和返回值都是纯 `long long`，不经过 `Val`，报错文案与擦除版一致）。
- 运行时侧这三个函数是 `static inline` + `__builtin_expect`，预测分支就是「没溢出」。
- `--no-int-ck`（或环境变量 `IMPOR_NO_INT_CK=1`）关掉逐运算检查，换成裸 C 算术 —— 这时才能和手写 C 打平，但也就放弃了 E1012。

### 实测（1e8 累加，8 轮交替取最小值，同一台机器）

| 路径 | 时间 | 相对手写 C |
| --- | --- | --- |
| 手写 C（`gcc -O2`） | 43.7 ms | 1.00× |
| 4.6 擦除版（`--no-fast --no-mono`） | 296.7 ms | 6.8× |
| 4.7 原生实例 + E1012 检查（默认） | 71.8 ms | 1.64× |
| 4.7 原生实例 + `--no-int-ck` | 43.1 ms | **0.99×** |

正确性：三条路径输出都是 `4999999950000000`；`add1(9223372036854775807)` 在带检查时报 `E1012` 退出 1，`--no-int-ck` 下回绕。

**没做到**：1e8 长循环压到 1.2× 以内，在保留逐运算检查的前提下没有达成。1e8 次溢出判定本身约 +25–28 ms，占比就在那儿。

### 开关

- `--no-mono`：整条关闭单态化（对比、排查用）。
- `--no-int-ck`：关闭原生实例的溢出检查。
- `impor build` / `impor run` 默认都用；构建摘要会多一行「单态化：N 个原生实例」。

### 边界（未做）

- 混合标注（`def f(a: int, b: float)`）不支持，要求全部参数与返回同一种标量。
- 原生子集不含：字符串拼接、内建调用（`print` 等）、`while` 里的非 `range` 迭代器、`try` / `catch`、类方法调用。
- 不做局部变量/返回值的类型推导：只按标注与调用点静态类型定型。
- `str` 与自定义类型不单态化。

## 一、4.5.0 的问题：泛型只有声明，没有实例

Impor 的泛型是**声明期约束 + 运行期擦除**：

```
def max2 < T >(a : T, b : T) -> T
    if a > b
        return a
    return b
```

4.5.0 生成的 C 只有一份：

```c
static Val f_123(Val l0, Val l1) { ... }   /* 全部走 rt_gt / rt_lt 等 Val 分派 */
```

`T` 在运行时不存在，每次比较都要经过 `Val` 的类型判断。**这不叫单态化，只是"能编译"。**

## 二、4.6 的做法：按调用点静态定型，生成专用符号

新增 `impor/monomorph.py`，在 `ctrans.gen_program` 生成 C 之前扫一遍 AST：

1. 收集**可用泛型**：`type_params == ["T"]`（单个类型参数），
   且所有参数的类型标注都是 `T`（或未标注）。
2. 扫**调用点**：`Call(callee=Var(name))`，实参个数与定义一致，
   每个实参都能静态定型，且所有实参同型。
3. 为该 `(函数名, 类型)` 生成原生 C 实例：

```c
/* 单态化：max2<T> → gp_max2_i64 实例（擦除版仍保留作回退） */
static Val gp_max2_i64(long long p_a, long long p_b) {
    long long v_r = 0;
    if (((p_a) > (p_b))) {
        return v_int(p_a);
    }
    return v_int(p_b);
}
```

4. 把调用点改派到实例：实参**解箱**、调用、返回值已装箱：

```c
({ rt_trace_push("max2", 12); Val _tr = gp_max2_i64((long long)(x).i, (long long)(y).i);
   rt_trace_pop(); _tr; })
```

`rt_trace_push/pop` 与擦除版保持一致，所以调用栈回溯不受影响。

**擦除版一律保留**。单态化是**加一条快路径**，不是替换实现 —— 任何没命中的调用点行为与 4.5.0 完全相同。

## 三、静态定型的规则（当前只认字面量）

| AST | 定型 |
| --- | --- |
| `Num(整数)` | `i64` |
| `Num(小数)` | `f64` |
| `UnaryOp(-/+, Num)` | 递归取子节点的类型 |
| 其它（变量、调用、下标、属性…） | 不定型 → 该调用点回退 |

这是**保守选择**：不猜变量类型，就不会猜错。代价是 `max2(a, b)`（a/b 是变量）不命中实例。

## 四、原生子集（函数体能生成原生 C 的范围）

支持：

- 表达式：整型/浮点字面量、`bool`、参数与局部变量、`+ - *`（`f64` 另加 `/`）、
  比较 `> < >= <= == !=`、`and`/`or`、一元 `- + not`、三元、**自递归调用**。
- 语句：`赋值`、`+= -= *=`、`return`（必须有返回值）、`if/elif/else`、`while`。

不支持（`NativeUnsupported` → 整个 `(函数, 类型)` 不生成实例，回退擦除版）：

- 字符串、`%`、整型 `/`（整除语义依赖运行时）、`for` 迭代器、`print` / 任何内建调用、
  调用其它函数（只允许自递归）、裸 `return`、`return` 类型标注不是 `T`。

**注意**：`ARITH` 只含 `+ - *`，整型实例遇到 `/` 会抛 `NativeUnsupported` 并回退 ——
这是刻意的，因为 Impor 的 `/` 是浮点除法，整型半态化容易给出不同于解释器的结果。

## 五、实测

用例：`examples/generics.impor`（`ident<T>` / `max2<T>` 各若干调用）。

生成的 C 里可见（`%TEMP%\irverify\mono\generics.c`）：

- `gp_ident_i64(long long)`
- `gp_max2_i64(long long, long long)`
- `gp_max2_f64(double, double)`
- 同时保留 `f_*` 擦除版

对拍：解释器输出与 C 产物输出**逐行一致**（`mono1.log`）。

性能（同一台机器，`-O2`，200 万次 `max2` 调用）：

| 版本 | 耗时 |
| --- | --- |
| 单态化命中 | **0.35 s** |
| 回退擦除版 | 0.45 s |

约 **22%** 提速。数字不大，因为函数体只有一次比较；调用次数再多，装箱/解箱的固定开销仍在
（`Val` 是结构体，实例边界上仍有一次 `v_int` 装箱）。要再快就得让单态化实例之间直接传原生值，
那是"类型化的中间表示"，不在这一版。

## 六、没做的（明确记录）

1. **只支持 `i64` / `f64` 两种实例**：`str`、列表、字典、自定义类型的泛型不单态化。
2. **不做类型推导**：只按字面量定型，变量/表达式实参一律回退。
3. **只支持函数级泛型**：类/结构体上的类型参数没有处理。
4. **IR 路径不单态化**：`impor ir --build` 走 `cir`，目前仍按擦除视图生成；
   提速只在 `ctrans`（默认 `build` / `build --fast`）生效。
5. **不做跨函数传播**：`f<T>` 调 `g<T>` 时不会连锁生成实例。

cd <仓库根>

py -3.11 Impor.py run examples/generics.impor     # 两边输出应逐行一致

Python 启动器，不是 C 后端，看不到这一层。
