# Impor 三端能力矩阵（3.6.6 冻结；3.6.14 复核）

日期：2026-11-15

三端 = 解释器（`impor run`） / C 后端（`impor build`，ctrans + c_runtime.c） / 自举 imporc（`imporc.exe`，语法子集）。

原则：**只有“支持”和“明确拒绝”两种状态。** 不允许“解释器能跑、构建端静默生成一个行为不同的 exe”。

## 3.6.11 决策：管道与字符串插值保留

3.6.11 明确决定：**不删除管道 `|>`，也不删除字符串插值 `"x = {expr}"`。** 保留语法不等于三端等价，各端边界如下：

| 能力 | 解释器 | Python 转译器 | C 后端 | 自举 imporc | 契约 |
|---|---|---|---|---|---|
| 管道 `|>` | 支持 | 支持 | **明确拒绝**：`C 后端暂不支持：管道运算符 \|>` | 拒绝（子集不含） | 解释器/转译器一致；C 后端构建前报错 |
| 字符串插值 `"x = {expr}"` | 支持 | 支持 | 支持 | 拒绝（子集不含） | 解释器 / 转译器 / C 后端一致；自举不承诺 |

管道在 C 后端由 `impor/ctrans.py` 的 `_UNSUP_NODE["Pipe"]` 明确拒绝，不会静默生成行为不同的 exe；自举 imporc 只承诺语法子集，遇到子集外语法必须编译失败。

## 3.6.13 路径复核：中文 / 空格 / 括号安装目录

3.6.13 不改语言语义，只修“安装路径”这一层。验收路径：

`C:\Users\41482\Desktop\总Impor文件\Impor(I++) 3.6.13\`

| 检查项 | 结果 |
|---|---|
| 目标 3 条（imporc 闭包 / 模块值 / 包内嵌套构建） | `Ran 3 tests in 3.300s / OK` |
| 桌面路径完整默认 suite | `Ran 566 tests in 123.649s / OK` |
| 仓库路径完整默认 suite | `Ran 566 tests in 140.922s / OK` |
| `Impor.py build examples\hello.impor` | 成功，exe 可运行 |
| `_mingw.h` 随包分发 | 存在 |

修复分两层：

1. **命令层**：`imporc` 调 tcc 的输出路径、`run` 模式执行产物路径、`imporc_args.txt` 里的脚本/输出路径、`cmd /c` 整条命令，全部用双引号包裹。空格和括号不再拆断命令行。
2. **C 运行时层**：Windows 下路径按 UTF-8 传入，但 `fopen` / `CreateProcessA` 按 ANSI 解释。`c_runtime.c` 改为 UTF-8 → UTF-16 后走 `_wfopen` 与 `CreateProcessW`，中文目录可被 `fileread` / `filewrite` / tcc 子进程正常访问。

这两层缺一不可：只加引号仍有 2 条 `fileread: 无法打开文件` 和 1 条 tcc `could not write`；只改 Unicode 仍会被空格/括号截断。

## 矩阵

| 能力 | 解释器 | C 后端 | 自举 imporc | 契约 |
|---|---|---|---|---|
| 整数/浮点/字符串/布尔、算术、比较 | 支持 | 支持 | 支持 | 一致 |
| `if` / `while` / `for range` / `do-until` | 支持 | 支持 | 支持 | 一致 |
| 函数、递归、数组、类/结构、`match` / `switch` | 支持 | 支持 | 支持 | 一致 |
| JSON `json_encode` / `json_decode` | 支持 | 支持（已实测构建并运行） | 拒绝（子集不含 JSON 运行时） | 支持端语义一致；自举端必须明确报错 |
| 正则 `regex_match` / `regex_find` / `regex_replace` | 支持 | 支持（已实测构建并运行） | 拒绝 | 同上 |
| `lambda` 表达式 | 支持 | 支持（已实测构建） | 拒绝 | 同上 |
| `filelist` / `filemkdir` / `fileexists` / `filesize` | 支持 | **明确拒绝**：`build（C 后端）不支持：未定义函数：filelist` | 拒绝 | 构建前报错，不生成 exe |
| FFI（Windows DLL） | 支持 | 明确拒绝（ctrans 未支持节点/内建） | 拒绝 | 构建前报错 |
| 图形化编辑器 / LSP / 调试器 | 支持 | 不适用 | 不适用 | 不属于语言运行时契约 |
| 中文标识符 | 支持 | 部分支持 | **明确拒绝**：`暂不支持非 ASCII 字符` | 自举端不是等价后端 |

## 已执行的证据

- JSON：`impor build _compat_json.impor` 成功，生成 exe 运行输出 `[1,2]`。
- 正则：`impor build _compat_re.impor` 成功，exe 输出 `['1', '2']`。
- Lambda：`impor build _compat_lambda.impor` 成功。
- 文件 API：`impor build _compat_file.impor` 退出码 3，明确提示 C 后端不支持 `filelist`，并建议改用 `--backend=py` / `impor run`。
- 自举非 ASCII：`impor/ccomp.c` 明确输出“暂不支持非 ASCII 字符（当前自举子集仅英文标识符）”。

## 结论

1. **JSON / 正则 / lambda 不再是“解释器单端功能”**：C 后端已经能用，路线图 v6.0 的第 12、13 行已过期。
2. **文件 API / FFI 仍是解释器专用**，但 C 后端会在构建前明确拒绝，不会静默产出错误 exe。
3. **自举 imporc 是语法子集，不是第三套等价运行时**；它只承诺子集，超出子集必须报错。
4. 仍缺的是“把文件 API / FFI 做成 C 后端等价”，这是 3.6.7 的候选，不在 3.6.6 里假装完成。
