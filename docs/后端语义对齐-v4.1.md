# 后端语义对齐与五条批评的处理（v4.1 工作区）

日期：2026-11-22
适用范围：桌面发布件 `Impor 4.0.0`（`VERSION` 未动，改动记在 `CHANGELOG.md` 的 `## [未发布]`）
口径：只写能用命令复现的结论；未做的单列，不写成"已解决"。

## ① 同一份源码两个答案

**问题成立，且比批评里写的更细：现在不是两个答案，是三条路径三种行为。**

改前实测 `print(9223372036854775807 + 1)`：

| 路径 | 改前行为 |
| --- | --- |
| `impor run`（默认，透明编译走数值快路径） | 报错 `数值快路径的 64 位整数溢出（加法）`，退出码 1 |
| `impor build`（完整 Val 后端） | 报错 `整数溢出：超出 64 位有符号整数范围` |
| `impor run --no-native`（纯解释器） | 打印 `9223372036854775808`（Python 任意精度） |

同一句话、三个结果，而且两条报错文案还不是同一句。

**本次改动**

1. 新增 `impor run --int64`（别名 `--strict-int`），把解释器切到与 C 后端同一套 int64 语义：`+ - * /` 中的加减乘、一元取负、整数字面量越界，一律报 `E1012`。
2. 三处文案统一为 `整数溢出：超出 64 位有符号整数范围 [E1012]`（`impor/cfast.py` 的 `iovf`、`impor/c_runtime.c` 的 `rt_ck_*`、解释器新增的 `_i64`）。
3. 修掉一条真实绕过：`visit_BinOp` 的"双数字字面量"快速路径在闸门之前直接 `return a + b`，所以第一版 `--int64` 对 `print(MAX+1)` 无效；现已并入同一闸门（这是本次调试抓到的第二个 bug）。
4. `--int64` 会强制关掉解释器内部的 Python 转译快路径（`_run_fast` 走的是 `exec` 生成的 Python 源码，绕过所有 `visit_*` 闸门）。

**现在的矩阵（可直接跑）**

```
impor run  t.impor            # int64 快路径：E1012，退出码 1
impor run t.impor --int64     # 解释器对齐：E1012，退出码 1
impor run t.impor --no-native # 任意精度：9223372036854775808
impor build t.impor -o t.exe  # C 后端：E1012，退出码 3
```

**没做的（需要你拍板，不是技术障碍）**

默认解释器仍保留任意精度，因为它是 4.0.0 已承诺的能力（`README` 第 13 行、`docs/3.13-后端能力边界.md`、`docs/新手教程.md` 第 474 行都写了）。真要"默认只有一种整数"，只有两条路：

- **把默认切成 int64**：改 `Interpreter` 默认值 + 改 3 处文档 + 让现有依赖大整数的测试与示例迁移；收益是默认行为唯一，代价是"任意精度"从默认能力降级为 `--bigint` 选项。
- **把 C 后端切成任意精度**：要在 `c_runtime.c` 里实现 bignum（远大于一个补丁窗口的工作量，且会拖慢 `--fast`）。

在此之前，`--int64` 至少把"跨后端是否安全"变成一条 CI 可跑的检查，而不是靠人记。

## ② "唯一写法"只做了一半

**问题成立在口径，不在实现。**

实测计数（231 个 `.impor`，排除 `impor/tcc/`）：

| 项 | 数量 |
| --- | --- |
| 首行带 `important<<…` 头部 | 159 |
| 使用 `elseif` 的文件 | 3 |
| 使用 `switch` 的文件 | 0 |
| `examples/` 文件数 | 72 |
| 其中含缩进块的文件 | 38 |

也就是说：仓库自己在用缩进块（38/72 的示例），而宣传语是"唯一写法"。这不是要多删语法，而是**规范没把边界写清**。

**本次改动**：`docs/语言规范.md` §0 新增一条"唯一写法"的准确边界——

- 删除的 12 类是清单式列出的（`func`/`loop`/`local`/`let`/裸 `print`/`:=`/`++`/`--`/`&& || !`/`<>`/`then`/`unless`/`for each`/`of`/`1..n`/C 风格 `for`/`do..until`）；
- **长期兼容、不在删除清单**：`elseif`/`switch`、冒号+缩进块、三种注释、文件头标记；
- 明确"唯一写法"指的是这 12 类被删除，不是要求全语言单排版。

**没做的**：没有加 `impor lint --style` 去把别名/缩进块标黄。理由是仓库存量里 3 个文件用 `elseif`、38 个示例用缩进块，先给统计（上表）比先给告警更合适；真要推进"新代码只写主写法"，建议先跑一个"存量清单"再决定是否开 lint 告警。

## ③ 仪式性语法：文件头

**问题成立在"税"，不在语法。**

头部自 v2.3.1 起就是可选的，但两件事仍在收税：`impor new` 的 4 个模板都写它，`strip_header` 缺头部时每次都往 stderr 打提示。

**本次改动**

- `NEW_TEMPLATE` / `NEW_LIB_TEMPLATE` / `NEW_GAME_TEMPLATE` / `NEW_PKG_FILES["main.impor"]` 四处删除首行头部；实测 `impor new a.impor` 首行现在是 `// Impor (I++) 脚本`，`impor new pkgx --template pkg` 的 `main.impor` 首行是 `// pkgx 项目入口`。
- 缺头部默认**完全静默**，旧提示保留在 `IMPOR_HEADER_HINT=1` 后面。
- 已有 159 个文件的头部继续解析，`tools/check_fmt_all.py` 仍校验逐字一致（避免老仓库分裂出第二种头部写法）。

**没做的**：没有物理删除这 159 个文件的头部。那是全量源码改写，收益（少一行）与风险（碰 159 个文件的 diff）不成比例；要不要做请你定。

## ④ 几处会绊人的小设计

| 项 | 状态 |
| --- | --- |
| 递归上限 3200 写死 | **已修**：`--max-depth N` / `IMPOR_MAX_DEPTH`，树遍历与快路径同步；Python 帧上限按深度等比放宽（`max(200000, depth*70)`）。`tests/test_v4_backend_parity.py` 用 `--max-depth 6` 与 env 两条路径锁定 |
| 无整除运算符（`//` 被注释占用） | **修正前提**：`div(a, b)` 内建早就存在（`builtins.py` `builtin_div`，向下取整，与 C 端 `rt_idiv` 一致），缺的是文档——规范里原来只写「整除用 `to_num`」。4.0.1 已在 `docs/语言规范.md` 的运算符一节写清 `div` / `%` 语义与恒等式 `a == div(a,b)*b + (a%b)`，并补 `tests/test_v4_backend_parity.py::TestIntegerDivision` 四端比对。不加 `//` 符号仍是对的：`//` 是注释定界符 |
| `var`/`set` 比 `=` 长、`nonlocal` 后可省 `set` | **未做**：这是 4.0 的核心写法，改名会影响 231 个文件与自举编译器 |
| `if c print(x)` 悬挂 else | **未做**：未实测该写法在本版的解析结果，不做"已确认风险"的断言；要改先补一条用例 |
| 三种注释并存 | **保留**：都已在规范 §0 写明，属兼容面不是错误 |

## ⑤ 生态与并发

**这五条里唯一没有动手的。**

实测现状（**v4.1 时点快照**）：`impor/std/` 10 个真模块（algo / collections / fs / http / json / mathx / path / regex / text / time）+ `__pkg__.impor`；无线程 / 协程 / channel；无泛型；`impor pkg` 有 install/remove/lock/registry，但没有公共包仓库。

本轮只把包管理的"装完即可 import"打通（见 `docs/包管理与-vendor.md`），生态本体没有新增模块。这段不写成"已规划"，只作为待办：按族补 `std`（crypto / compress / csv / log / testing / 时间解析优先），并发另开 RFC。

> **v4.2 更新（2026-11-22，本节已过时，仅作历史记录）**：标准库 15 → 16 个真模块（新增 `sort` / `random` / `stats` / `thread` / `atomic`，并把一直漏接线的 `csv` 补进 `__pkg__.impor`）；并发落地 OS 线程 + 互斥锁 + 原子量（解释器 / Python 转译 / C 后端三端一致）；泛型支持声明位类型参数（`def max2<T>(a: T, b: T) -> T`）。现行口径见 `docs/语言规范.md` §5.1 与 §24。
