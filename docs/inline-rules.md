# 内联 pass：判据、开关与实测

> 版本：4.7.2　实现：`impor/inline.py`　接入点：`impor/ctrans.py::c_transpile`（AST 层，完整后端与 IR 后端共用）

## 1. 为什么单独设计判据

"把函数调用展开"听起来简单，但内联会动三样东西，每样都可能悄悄改变语义：

1. **副作用次数**：形参被用两次时，实参表达式会被求值两次；
2. **报错位置**：错误原来指向函数体内部，内联后指向哪里，必须先定死；
3. **栈帧**：异常栈少一层，用户看到的"调用链"会变。

所以本 pass 的判据是**白名单式**的：不满足就老实不内联，绝不"尽力而为"。

## 2. 候选函数判据（全部必须满足）

| # | 判据 | 理由 |
| --- | --- | --- |
| 1 | `body` 恰好 1 条语句，且是 `Return(expr)` | 保证没有控制流，展开后不会引入分支/循环 |
| 2 | 参数 ≤ 4 | 超过就不是"小函数"了 |
| 3 | 非 `async`、无 `type_params` | 泛型交给 `monomorph` 单态化，不重复造轮子 |
| 4 | `expr` 节点数 ≤ `IMPOR_INLINE_MAX_NODES`（默认 40） | 防炸开 |
| 5 | `expr` 内不含 Call/Await/Lambda/NewInstance/SuperCall/Assert/Raise/Assign/CompoundAssign/AttrSet/IndexSet/Import/Print/ExitScript | 有副作用或有控制流的一律不内联 |
| 6 | `expr` 不引用函数自身名 | 自递归内联必然无限展开 |

## 3. 调用点判据

| # | 判据 | 理由 |
| --- | --- | --- |
| 1 | `callee` 是 `Var(name)` 且命中候选表 | 方法/属性调用不在本 pass 范围 |
| 2 | 实参个数 == 形参个数 | 默认参数/变参不处理 |
| 3-1 | 形参出现 k=0 次 → 实参必须是纯的（Num/Str/Bool/Null/Var） | 否则会把副作用丢掉 |
| 3-2 | k=1 → 允许 | 求值次数与原来一致 |
| 3-3 | k>1 → 实参必须是纯的 | 否则重复求值，语义改变 |
| 4 | 嵌套层数 ≤ `IMPOR_INLINE_DEPTH`（默认 2） | 防炸开 |

## 4. 报错位置判据（这一条最容易出错，单独定死）

> **内联进来的整棵子树，`lineno` / `col` 一律改写为调用点的行列。**

后果：E1012（整数溢出）、除零、类型错误、下标越界等运行期错误，报的是**源码里写着调用的那一行**，
与内联前的"栈顶是调用点"一致；而且因为少了一层调用，栈更短更清楚。

实测对照（`tests/inline/inl2.impor`，第 8 行 `var r: int = mul2(big)` 触发溢出；函数体在第 4 行）：

内联开启：
```
运行错误: 第8行: OverflowError: 整数溢出：超出 64 位有符号整数范围（乘法） [E1012]
  8 │ var r: int = mul2(big)
调用栈（自顶向下）:
  <main>
```

内联关闭（`IMPOR_NO_INLINE=1`）：
```
运行错误: 第4行: OverflowError: 整数溢出：超出 64 位有符号整数范围（乘法） [E1012]
  4 │     return x * 2
调用栈（自顶向下）:
 -> mul2（第8行）
```

两者指向的都是**同一次调用**：内联版指到调用点（第 8 行），非内联版指到函数体（第 4 行）再补一层
`mul2（第8行）` 说明调用点。用户看到的位置信息没有丢，只是内联版更贴近"自己写的那一行"。

## 5. 开关与统计

| 环境变量 | 作用 |
| --- | --- |
| `IMPOR_NO_INLINE=1` | 关闭整个 pass（回归对照） |
| `IMPOR_INLINE_MAX_NODES` | 候选体积上限，默认 40 |
| `IMPOR_INLINE_DEPTH` | 最多叠几层，默认 2 |
| `IMPOR_INLINE_TRACE=1` | 逐条打印「函数@行 -> 调用点行」 |

构建摘要会多一行：`内联：N 处单表达式小函数已在调用点展开（报错位置仍指向调用点）`。

## 6. 实测用例（`tests/inline/`）

| 用例 | 内容 | 期望 | 实测 |
| --- | --- | --- | --- |
| `inl1.impor` | `add1(twice(sq(i)))` 三层嵌套，`i=3` | 受 `IMPOR_INLINE_DEPTH=2` 限制只展开 2 层 | ✅ `内联：2 处`，输出 `sum=19` / `19`（手算 2×9+1=19） |
| `inl2.impor` | `mul2(big)` 溢出，调用点第 8 行 | 报错在第 8 行 | ✅ `第8行 … E1012`，栈 `<main>`；关闭内联为 `第4行 … mul2（第8行）` |
| `inl3.impor` | `dbl(len(xs))`，形参用两次、实参是 Call | 跳过（实参不纯） | ✅ 摘要无内联行，输出 `6` |

## 7. 已知边界（未做）

- 方法调用（`obj.m(x)`）、带默认参数的函数、变参函数：不内联。
- 多语句函数（哪怕只有 `if (...) return a; return b;`）：不内联 —— 需要 SSA 化的表达式化改造。
- 内联不做"死函数删除"：被全部内联后定义仍在，交给 gcc 的 `-O3` + `static` 处理。
