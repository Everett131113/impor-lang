# 类型注解边界（3.13.0）

Impor 的类型注解是**可选的静态提示**，不是类型系统。

## 会检查的

- `var x: int = 5` / `const P: str = "a"`：初始化是字面量时，检查字面量类型与注解是否匹配。
- 函数返回注解：`return` 后是字面量时，检查字面量类型与注解是否匹配。
- 这些检查在 `run` / `run-dbg` / `compile` / `build` 解析后执行，失败退出码 2。

## 不检查的

- `var x: int = 5` 之后 `set x = f()`：不追踪赋值后的值。
- 变量经过分支、循环、函数调用后的类型。
- 容器元素类型、泛型、联合类型、可空性。
- 运行时强制：解释器不会因为注解在运行时拒绝一个值。
- C 后端：注解只用于 C ABI 导出签名；普通代码的注解不产生运行时检查。

## 为什么保留

注解在 C ABI（`export func add(a: int, b: int) -> int`）和教学示例里仍有价值：它能提前抓“字面量写错类型”这类低级错误。但它不能承诺“类型安全”。

## 写法建议

- 需要稳定契约的跨语言边界，写完整注解并走 `--lib` / C ABI 检查。
- 普通脚本可以不写注解；不要因为写了 `: int` 就认为运行时会被强制。
