# Impor (I++) 语言规范 v3.11.0

本文档描述 Impor（读作 I++）的当前语言规范，以 v3.11.0 实现为准。

版本线说明：v3.11.0 是当前稳定版；文档和历史记录中出现的 v4.x / v5.x / v6.x / 7.3.0 是历史实验线，只用于解释旧代码、旧日志和旧发行物，不代表当前版本号，也不代表当前能力。当前稳定线从 v3.8.0（工作区 2.0 / 编辑内核 3.0）延续到 v3.11.0（六格 C ABI 矩阵与 bench-spec）。

- 实现：词法分析 → 递归下降语法分析 → AST → 树遍历解释器；**C 后端（`build` 命令）是唯一发布路径**：Impor AST → C 源码 → 随包分发的 tcc 原生编译，产出不依赖 Python 的独立 exe 或 DLL（`--lib`）；Impor→Python 转译器（`compile` 命令）只做开发兼容，不承担发布。
- 文件编码：UTF-8。块结构推荐**大括号 `{ }`**（标准形式）；旧工程的冒号 + 缩进块继续兼容，同一文件不要混用。
- 注释：`//` 单行、`#` 单行、`/* ... */` 多行（可跨行）。
- **v3.3 三端一致性**（本版只消除不一致与崩溃，不新增语言特性）：
  - 字符串 `len` / 下标 / `strcut` 一律**按字符**（C 后端按 UTF-8 编码单元计数），下标支持负数、越界报错；字符串字面量可直接下标（`"你好"[1]` → `好`）。
  - C 后端整数为 **64 位有符号（int64）**，加/减/乘溢出时报 `整数溢出：超出 64 位有符号整数范围`。解释器侧仍是 Python 大整数——这是唯一保留的语义差异，写跨后端程序时请确保数值落在 int64 范围内。
  - `1 == true` 为 `true`；`1 + "a"` 报 TypeError（不再隐式拼接，需 `to_str()` 显式转换）；`"ab" * 3` 为 `"ababab"`（字符串 × 整数重复，次数 ≤ 0 得空串）。
  - 解释器递归上限约 3200 层（`sys.setrecursionlimit(200000)` + 调用深度闸门）；超限报 `RecursionDeep`，提示改用循环，避免 C 栈溢出变成整进程段错误。快速后端与树遍历统一为 3200 层。
  - C 编译失败（tcc）会把 C 行号反查回 Impor 源码行，输出 `C 编译错误: 第N行 列M` + 源码行 + 指示符，而不是裸吐 tcc 英文错误。
  - `conformance/` 提供 23 个脚本 × 三后端（解释器 / C 后端 / 自举编译器）逐字节比对，已接入 CI。
- **v3.7.3 原生数值快路径（显式 opt-in）**：
  - `impor build FILE.impor --fast`（别名 `--fast-native`）只接受纯整数数值脚本，生成变量/参数为 `long long` 的 C 代码，不经过 `Val*` 装箱；默认 `impor build` 仍走完整 C 后端，语义不变。
  - 支持：整数变量与赋值/复合赋值、`while`、`if/elif/else`、顶层函数、`return`、`print`、`abs/min/max`、`+ - * %`、三元表达式；比较与 `and/or/not` 只允许用于条件，不能存成布尔值或打印。
  - 拒绝：浮点、字符串运算、容器、类、异常、嵌套函数、`for`、裸表达式、未知内建、布尔值存储/打印。CLI 返回码 3 并提示去掉 `--fast`，不静默降级。
  - 整数范围是 64 位有符号；超出会按机器整数回绕，不做解释器的任意精度与溢出报错。`%` 按 Impor 的符号规则实现，`% 0` 运行时输出 `division by zero` 并以 1 退出。基准中的 20x 只适用于纯整数循环，取模与递归明显低于 20x。
- **v3.7.2 关键字收敛**：
  - 空保留字全部降级；`KEYWORDS` 中每个词都必须能在 parser 中找到实际语法产生式，`tests/test_v372.py` 自动审计。
  - `static` / `readonly` / `async` / `await` / `this` / `defer` 是软关键字：保留语法语义，同时可作普通标识符。
  - 同义写法只推荐一套主写法：`def`（不是 `func`）、`elif`（不是 `elseif`）、`match`（不是 `switch`）、`while`（不是 `loop`）、`var`（不是 `let`）。别名仍可解析，但标为 deprecated；`impor fmt` 只输出主写法，LSP 补全只推主写法。
  - 主写法与别名的选择以本节为准；规范、教程、conformance、补全四处同口径。

## 1. 程序头部

每个 `.impor` 文件第一行可以是：

```
important<<DAY<<english("English"):
```

头部标记自 v2.3.1 起**可选**：缺失时仅给出警告、正常解析执行（用于版本标记，不再拒绝运行）。`impor new` 生成的模板默认带头部。

## 2. 变量与常量

```python
var x = 10            # 声明变量
var name = "Impor"    # 字符串
set x = 20            # 赋值（x 须已声明）
set obj.attr = 1      # 属性赋值
set arr[0] = 99       # 下标赋值
set self.name = name  # 类中给实例字段赋值（旧语法兼容）
```

- 关键字 `var` 声明、`set` 赋值；两者都支持 `对象.属性` 与 `数组[下标]`。
- 变量无需类型标注，类型由值决定：整数、小数、字符串、布尔、列表、字典、函数、类、实例、vec2、rgb。
- 真/假：`true` / `false`。
- 复合赋值：`+=  -=  *=  /=  %=`；支持普通变量，也支持**对象属性与下标**（`b.val += 10`、`a[0] += 5`、`d["n"] *= 2`）。
- 字符串：单引号或双引号，转义 `\n \t \\ \" \'`；三引号 `"""` 支持多行字符串（可跨行）。
- **字符串插值**（v2.9）：`"你好, {name}，今年 {n} 岁"`——`{表达式}` 在运行期求值并转为字符串；`\{` 与 `\}` 为字面花括号；插值表达式内不支持 `}`（避免与字典字面量歧义）。解释器与转译产物行为一致。
- **原始字符串**（v2.2）：`r"..."` / `r'...'` / `R"..."`，关闭转义解析、反斜杠原样保留（`print(r"a\nb")` 输出字面 `a\nb`）；`\"` 不结束字符串，反斜杠与引号都保留（与 Python 规则一致）。
- 列表：`[1, 2, 3]`；字典：`{"key": value}`，键可为字符串或数字。
- 下标与切片：`a[0]`、`a[-1]`、`a[1:4]`、`a[:3]`、`a[::2]`、`a[-2:]`；字符串与数组均支持，负索引从末尾计数、越界自动裁剪、负步长反向取；`step == 0` 报 `ValueError`，字典切片报 `TypeError`。
- 字典方法（v4.2）：`d.keys()`、`d.values()`、`d.items()` 返回数组；`d.get(k, 默认值)`、`d.has(k)` / `d.contains(k)`；`for k in d` 迭代键。`d[k]` 读写，缺失键读取报 `KeyError`。
- 字典与数组参与 `==` 时按内容深比较（嵌套数组逐元素、字典按键匹配后比较值）。

## 3. 运算符

| 优先级 | 运算符 |
|---|---|
| 高 | `( )` `[ ]` `.` 方法调用 `new` |
| | 一元 `-` `not` |
| | `* / %` |
| | `+ -` |
| | `== != < <= > >=` |
| | `and` |
| | `or` |
| | `|>` 管道（v2.9，左结合） |
| 三元 | `条件 ? 真值 : 假值` |

运算语义与 Python 一致：`/` 得小数、`//` 是注释不是整除（整除用 `to_num` 或 `int` 风格运算）。

**管道运算符 `|>`（v2.9）**：把左侧结果作为第一个参数传入右侧调用，专为链式数据流设计：

```python
5 |> add2 |> mul3          # == mul3(add2(5))，链式
3 |> add(10)               # == add(3, 10)，右侧调用参数自动后移
"hello" |> upper |> len    # == len(upper("hello"))，可接内建函数
[1,2,3] |> sum_arr         # == sum_arr([1,2,3])
```

- `x |> f` 等价 `f(x)`；`x |> f(a)` 等价 `f(x, a)`；左结合，可无限链式。
- 与 Python 等主流语言不同，管道把"数据流方向"写成代码阅读方向，是 Impor 的差异化特性。

**一元正负号（v2.4 宽松）**：`-`/`+` 除表达式开头外，也允许出现在二元/比较运算符右侧：
`a != -1`、`x * -2`、`a - -3`、`a >= -2 and a <= 2` 均合法。

## 4. 流程控制

冒号**可省略**（旧版承诺的 Pro 语法，v2.0 已支持）。

**v2.10 大括号块（新标准）**：代码块与缩进剥离，统一用大括号 `{}`（块内缩进被忽略）：

```python
if 条件 {
    语句
} elseif 条件2 {
    语句
} else {
    语句
}

while 条件 { 语句 }          # 大括号块可单行书写
if 条件 { 语句1; 语句2 }     # 块内用换行分隔多条语句
```

**quick 单行块**：块体仅一条语句时可省略大括号（同行使内容）：

```python
if 条件 print("单行")
for i in [1, 2, 3] print(i)
func f(x) { return x * 2 }
```

**旧缩进块完全兼容**（历史脚本不受影响）：

```python
if 条件:            # 冒号可选
    语句
elseif 条件2:
    语句
else:
    语句
```

```python
while 条件
    语句

loop                 # 无限循环，等价 while true
    语句

for x in [1, 2, 3]   # 遍历列表
for i in range(0, 10)   # 遍历 range
for ch in "abc"      # 遍历字符串
```

- `break` 跳出循环，`continue` 跳过本次迭代。
- `if/while` 条件后也可写冒号；`for` 的 `in` 关键字不可省略。

### 4.1 match-case 模式匹配（v2.2）

`match` 是**软关键字**（可作变量名），仅在语句位置触发模式匹配：

```python
match 值
    case 1:            # 字面量模式：数字 / 字符串 / 布尔 / 负数
        语句
    case "red":
        语句
    case v:            # 绑定模式：把被匹配值绑定到变量 v
        语句
    case _:            # 通配符：匹配一切（不绑定变量）
        语句
    else:              # 兜底分支（v2.4，也可写 default:，必须位于最后一个分支）
        语句
```

- case 块用缩进表达；每个 case 命中后执行其块并结束整个 match（无 fallthrough）。
- 未命中任何 case 时执行 `else:` / `default:` 兜底分支（v2.4 新增；没有兜底则静默跳过）。
- 绑定模式变量只在命中块内有效。

## 5. 函数

```python
def add(a, b)         # 或 func add(a, b)
    return a + b

var f = add           # 函数是一等值
func make_counter(x)
    def inc()
        nonlocal set x = x + 1
        return x
    return inc
```

- `def` 与 `func` 等价。
- `return` 可省略值（裸 return）。
- **隐式返回（v2.9）**：函数体最后一行若是表达式语句（函数调用或裸表达式），自动返回其值，无需写 `return`：

```python
func double(x)
    x * 2            # 末行裸表达式 → 自动返回 x*2

func report(x)
    print("计算中")
    x + 10           # 隐式返回 x+10（前面的 print 正常执行）
```

  与显式 `return` 完全等价；若末行不是表达式（如 `set`/`if`/`while`），函数返回 `none`，行为不变。
- 闭包：函数捕获外层变量；修改外层变量用 `nonlocal set x = ...`。
- 全局作用域修改：`global set x = ...`。
- 高阶函数：函数可作为参数传递、作为返回值。
- 递归支持。
- **裸表达式语句（v2.9）**：任意表达式可独立成行（求值并丢弃结果），如 `a + 2`；这是隐式返回与管道链式写法的语法基础。

## 6. 类与面向对象

```python
class Animal
    def __init__(name)
        set self.name = name
    def speak()
        print(self.name, "在叫")

class Dog(Animal)      # 继承
    def speak()
        super().speak()          # 调用父类方法（支持链式）
        print(self.name, "汪汪！")

var d = new Dog("旺财")
d.speak()
set d.age = 3          # 实例属性
```

- 构造函数为 `__init__`；`new` 时沿继承链查找构造函数（子类无 `__init__` 自动用基类）。
- 类字段在 `class` 体内用 `var x = ...` 声明，实例自动继承（基类优先）。
- `super()` 需要紧跟 `.方法名(...)` 使用，或裸调用。
- 方法内通过 `self` 访问实例；`set self.x = v` / `self.x = v` 均可写属性。

### 6.1 结构体 `struct`（v3.7）

`struct` 是**只含字段**的记录类型，用来替代「只为装几个字段而写一个类」的样板代码：

```python
struct Point
    var x = 0
    var y = 0

var p = new Point(3, 4)     # 按字段声明顺序传参
print(p.x, p.y)             # 3 4
set p.x = 10                # 字段可读写
```

- 体内**只允许** `var 字段名 = 默认值`；空结构体、重复字段、方法或其它语句都会报语法错误。
- 字段默认值在 `new` 时先按默认值初始化，再用构造实参按**声明顺序**覆盖；实参少于字段数时，缺省字段保留默认值。
- `struct` 是**软关键字**：只在语句开头、后跟标识符时才生效，`var struct = 1` 这类变量名不受影响，关键字总数不变。
- 与 `class` 的关系：`struct` 会被解析器脱糖为一个 `class`（自动生成 `__init__`），因此继承、`self`、方法调用等能力与普通类一致；区别只是**不能**在 `struct` 体内写方法。
- 三端一致：解释器 / Python 转译 / C 后端（`impor build`）/ 自举编译器（`imporc`）均支持缩进块与 `{ ... }` 大括号块两种写法（字段之间可用 `;` 分隔）。C 后端构造实参通过语句表达式临时数组传递，规避 tcc 对多元素复合字面量的限制。

### 6.2 枚举 `enum`（v3.8）

`enum` 用来给一组相关的整数常量起可读的名字：

```python
enum Color { RED, GREEN, BLUE }
enum Size
    SMALL
    MEDIUM = 5
    LARGE

print(Color.RED, Color.BLUE)    # 0 2
print(Size.MEDIUM)              # 5
print(Size.LARGE)               # 6（显式值之后继续递增）

func label(c)
    if c == Color.RED
        return "红"
    return "其它"
```

- 两种块写法都支持：`{ ... }` 大括号块与换行缩进块；成员之间可用逗号、分号或换行分隔。
- 不写值时从 `0` 开始自动递增；写 `成员 = 整数` 后，后续成员从该值继续递增。值只接受整数字面量（可带一元 `+` / `-`）。
- `Color.RED` 在解析期改写为内部整型常量，因此可以直接参与比较、算术与 `switch`；成员名写错、重复成员、空枚举、非整数值都会报语法错误。
- `enum` 是**软关键字**：只在语句开头、后跟标识符且随后是 `{` / `:` / 换行时才生效，普通变量或函数名 `enum` 不受影响，关键字总数不变。
- 三端一致：解释器 / Python 转译 / C 后端 / 自举编译器（`imporc`）均支持两种块写法；conformance `22_enum.impor` 验证三后端输出逐字节一致。

## 7. 异常处理

```python
exception AgeError              # 自定义异常类型

func check(age)
    if age < 0
        raise AgeError("年龄非法")

try
    check(-1)
catch AgeError e                # 按类型捕获：catch 类型 变量
    print("错误:", e.msg)       # 异常消息用 .msg
catch IndexError err            # 内置异常也可按名字捕获
    print(err.msg)
catch err                       # 通配捕获任意异常
    print("其他错误")
finally
    print("总是执行")
```

三种 catch 写法：`catch err`、`catch Type err`、`catch Type, e`。
- `raise 类型("消息")` 或 `raise 类型`。
- 捕获不匹配时自动重新抛出；`finally` 无论是否捕获都执行（只执行一次）。

### 7.1 异常链（v2.2）

```python
exception Inner
exception Outer
try
    try
        raise Inner("boom")
    catch e
        raise Outer("wrap", from e)      # 写法一：括号内 from
catch err
    print(err.msg)          # wrap
    print(err.cause.msg)    # boom
```

也支持括号外形式：`raise Outer("wrap") from e`。`err.cause` 为原始异常（无 cause 时为 None）。

### 7.2 异常携带调用栈（v2.2）

每个异常对象携带抛出点的完整调用栈快照，`catch` 块可访问：

```python
exception E
func inner()
    raise E("深")
func outer()
    inner()
try
    outer()
catch err
    print(len(err.stack))        # 3：main + outer + inner
    for f in err.stack
        print(f.name, f.lineno)  # 帧名与行号
```

Python 底层异常（如 `1/0`）统一包装为 ImporException 并携带调用栈；属性赋值边界（对数字/列表等设置属性）抛出清晰 `AttributeError`。

### 7.2.1 defer 延迟清理（v3.7.8）

`defer` 在进入函数/模块时注册一段清理代码，退出该作用域时执行；后注册的先执行（LIFO）。正常 `return`、异常退出、`exit` 都会执行。

```python
func work()
    defer { print("close file") }
    defer { print("release lock") }
    print("body")
    raise ValueError("boom")
```

同一函数内输出顺序为：`body` → `release lock` → `close file`。异常继续向外传播；`defer` 体内的异常会覆盖原异常。

**边界**：
- 作用域是函数/模块，不是 `if`/`for` 块；块内 `defer` 仍在函数退出时执行。
- 模块顶层 `defer` 在脚本结束时执行。
- `defer` 是软关键字：`var defer = 1`、`defer()` 仍是普通标识符。
- `defer` 体内不能写 `return` / `break` / `continue`（编译期报错），避免与外层控制流冲突。
- Python 转译后端支持；C 后端明确报 `defer 延迟块（C 后端暂不支持）`，不静默跳过。

### 7.3 调试系统（v2.2）

**CLI 交互式调试**：`impor run-dbg 程序.impor`（启动即暂停第一行）

```
命令：
  n / next      步过
  s / step      步入
  o / out       步出（返回调用方后停在下一语句）
  c / continue  继续执行
  b 行号        设置断点（b 5）
  b 行号 if 表达式  设置条件断点（b 6 if x > 10；条件为真才暂停）
  b（无参数）   列出全部断点（含条件）（v2.12）
  del 行号      删除单个断点；del（无参数）删除全部（v2.12，d 为别名）
  p 表达式      求值并打印任意表达式（v2.5：p a + b，不再局限于单变量）
  bt            打印调用栈（自顶向下）
  l             打印当前帧局部变量
  h             帮助
  q             退出
```

脚本内 `breakpoint()` 也可触发暂停。GUI 编辑器「调试」提供同能力面板：调用栈 + 当前帧局部变量窗口 + 步入/步过/步出/继续按钮。断点行号与暂停位置均以**源码行号**为准（自动处理头部标记偏移）。

### 7.4 断言（assert，v2.8）

`assert 表达式`：条件为假时抛出 `AssertionError`（消息"断言失败"），可被 `try/catch AssertionError e` 捕获；常用于写测试与前置条件校验。

```python
assert 1 + 1 == 2          # 通过
assert x > 0               # 假 → AssertionError

try
    assert score >= 0
catch AssertionError e
    print("校验失败:", e.msg)
```

`assert` 是保留关键字（v2.8 起），不可用作变量名。转译产物（impor compile）语义一致：假时抛 Python `AssertionError`。

### 7.5 语法诊断格式（v2.8）

解析错误与运行时错误统一输出**行列号 + 源码行 + 波浪线（^）指位**：

```
impor: 语法错误: 第3行 列7: 期望 ID，得到 '='
  var x =
        ^
```

- 行号为源码真实行号（自动处理头部标记偏移）；列号 1 起。
- 表达式缺失等无具体 token 的位置列号为 0，波浪线指向行首。
- LSP 诊断（编辑器中波浪线）同步携带列号。
- 需要完整调试栈时设置环境变量 `IMPOR_DEBUG=1`。

## 8. 模块与 import（v2.1 模块系统）

### 8.1 导入语法（兼容旧写法）

```python
import mymod                     # 原有：导入整个模块对象（兼容保留）
import mymod as mm               # 导入并起别名
import pkg.sub                   # 点分隔：目录包 / 子模块（绑定顶层包名）
import math                      # Python 标准库（白名单）
import important.math            # 旧式路径写法（等价 import math）
from mymod import hello, calc    # 选择性导入
from mymod import hello as hi    # 导入并起别名
from mymod import *              # 导入全部对外符号
from .utils import tool          # 相对导入：当前包
from ..common import config      # 相对导入：父包
```

- **use 关键字（v2.12）**：`use std.text` 等价于 `from std.text import *`（中文写法 `用`），
  用于把模块的全部对外符号注入当前作用域。示例：`use std.mathx` 后可直接调用 `gcd(a, b)`。
- 导入解析顺序：**用户 `.impor` 模块/包优先 → 回退宿主 Python 模块**（`important.` 前缀直入 Python）。
- 相对导入（`from . / from ..`）**仅允许在包内使用**；主程序脚本使用会报错。
- 区分逻辑模块名与文件路径：逻辑名用点分隔（`pkg.sub`），搜索路径下先找目录包 `__pkg__.impor`，再找 `.impor` 文件。

### 8.2 导出与私有符号（export）

模块文件内只有被 `export` 标记的顶层符号对外可见；未标记的属于模块私有。

```python
# mymod.impor
func helper()
    return "私有辅助，外部看不见"
func calc(a, b)
    return a + b
export calc          # 单名导出
export { calc }      # 批量导出
```

兼容规则：
- **没有写任何 export 的模块**：全部顶层符号默认导出（旧脚本完全兼容）。
- **写了至少一条 export**：进入严格模式，只有被导出的符号对外可见，其余全部私有。
- export 不存在的名字 → `ExportError`。

### 8.3 目录包（Package）

文件夹作为包，包目录下放 `__pkg__.impor` 作为包入口；包内可放子模块、子包。

```
mygame/
    __pkg__.impor      # 包入口，可 export 聚合对外 API
    graphics.impor
    physics.impor
    utils/
        __pkg__.impor
        math.impor
```

```python
import mygame.graphics
from mygame.utils.math import vec_add
```

- `__pkg__.impor` 可用相对导入聚合子模块符号并 export（包的对外 API）。
- 子模块自动挂到父包（`import pkg.sub` 后 `pkg.sub` 可访问）。

### 8.4 模块缓存与循环导入

- 完整模块缓存：逻辑名 → 模块对象，含加载中 / 加载完成 / 加载失败状态。
- 循环导入**不报错**：加载前先置缓存，循环回导返回部分初始化的模块对象（参考 Python sys.modules 语义）。
- 加载失败的模块移出缓存，可再次尝试。

### 8.5 模块元信息与 reload

每个模块对象自带元信息（不可被模块代码覆盖）：

| 属性 | 说明 |
|---|---|
| `__name__` | 模块逻辑名 |
| `__file__` | 源文件路径 |
| `__is_package__` | 是否目录包（布尔） |

`reload(模块名)` 内置函数：原地重新加载模块，既有引用自动看到新内容（开发调试用）；加载中 reload 报 `ImportCycleError`。

### 8.6 模块相关异常

| 异常 | 场景 |
|---|---|
| `ModuleNotFound` | 模块/包找不到（既无 .impor 也无 Python 模块） |
| `ImportCycleError` | reload 加载中的模块 |
| `ExportError` | export 不存在的名字 |

### 8.7 项目配置（impor.toml）与 CLI

项目根目录放 `impor.toml`，`impor run` 自动读取（搜索路径相对项目根）：

```toml
[project]
name = "demo_game"
version = "0.1.0"
entry = "main.impor"
sandbox_default = false

[module_search_paths]
paths = ["./lib"]

[dependencies]
impor_std_utils = ">=0.2"
```

CLI 子命令：

```

impor run-dbg FILE        # 命令行交互式调试（断点/单步/栈/变量）

impor reload mymod        # 加载/重新加载模块（开发调试）
impor check-imports FILE  # 静态检查导入：缺失模块、循环导入
impor pkg init [目录]     # 生成项目骨架（impor.toml + 入口 + lib）
```

impor new NAME --template pkg   # v2.12：目录包项目骨架（impor.toml + main.impor + lib/NAME_lib/ 包）
impor check FILE          # v2.12：聚合检查：语法 + 导入 + lint + 格式（任一失败返回非 0，可接 CI）
```

## 8.8 内置标准库（v3.9）

随解释器内置的 Impor 源码标准库（目录 `impor/std/`，纯 Impor 编写），两种方式使用：

```python
use std.text                     # 注入全部对外符号（等价 from std.text import *）
use std.mathx
import std.collections as coll   # 常规导入形态
use std                          # v3.9：一次注入四个子模块对象（algo / text / mathx / collections）
print(algo.sorted([3, 1, 2]))     # 通过模块对象访问
```

| 模块 | 导出符号 |
|---|---|
| `std.text` | `split` `join` `trim` `upper` `lower` `replace` `contains` `starts_with` `ends_with` `char_at` `substring` `repeat` `pad_left` `pad_right` `index_of` `count_sub` `split_lines` `is_blank` |
| `std.mathx` | `gcd` `lcm` `fact` `fib` `is_prime` `sum` `avg` `min_of` `max_of` |
| `std.collections` | `map` `filter` `reduce` `reverse` `contains` `count` `uniq` `first` `last` `find` `find_index` `take` `drop` `flatten` |
| `std.algo` | `sorted` `sorted_desc` `index_of` `bsearch` `min_index` `max_index` |

v3.9 新增函数只依赖三端共有内建（`strpad` / `strcut` / `arrappend` / `arrdup` / `len` / `div` / 下标），解释器、Python 转译与 C 后端语义一致；`std.text` 的旧函数仍依赖 Python 宿主方法，C 后端暂不支持。

### 8.8 C 后端与 imporc 的模块导入（v4.3）

`impor build` 与 `imporc` 在编译期把被导入模块的 AST 拼接进主程序，产物仍是独立 exe，不执行模块代码也不依赖 Python。

- 支持 `import m`、`import m as mm`、`from m import a`、`from m import a as b`、`from m import *`、`import pkg.mod`、`import pkg.mod as pm`、相对导入与目录包 `__pkg__.impor`。
- imporc 同样支持上述全部形式；函数体内的嵌套 `import` 会被提升为编译期内联，运行时通过模块对象读取。
- 搜索顺序与解释器一致：脚本目录、当前目录、`impor.toml` 搜索路径；`std.*` 走内置标准库。
- 模块内被实际引用的函数/类/变量才保留，未引用定义与不可达死代码会被裁掉（因此模块里存在 C 后端不支持的写法，只要没人调用，不影响编译）。
- 模块内符号统一改名为 `__m_<模块>_<符号>`（imporc 为 `mi_<模块>_<符号>`），不同模块的同名函数/类可同时导入。
- 模块顶层语句会随主程序执行；模块对象可赋值、传参、打印与 `type_of`。不支持嵌套类、Python 模块导入，以及跨模块访问未导出符号。

## 14. 工具链（v2.3 P1）

### 14.1 静态分析（impor lint）

`impor lint 文件.impor` 对源码做静态语义检查，输出 `文件:行:列 [严重度] 消息`：

| 检查 | 说明 |
|---|---|
| 未定义变量 | 读取未声明的变量（排除关键字/内建名/`self`/`super`） |
| 未使用变量 | 函数/`for`/`catch`/`case` 作用域内声明后从未读取（模块级不报） |
| 未使用导入 | `import` / `from-import` 引入的名字从未使用 |
| 不可达代码 | `return`/`break`/`continue`/`exit` 之后继续出现的语句 |
| 参数数量不匹配（v2.5） | 函数调用实参个数与用户函数定义参数不符；内建函数按签名表检查（`len`、`clamp`、`strjoin` 等） |

v2.4：lint 先预声明模块级全部名字，函数/顶层对**后声明的函数与变量**前向引用不再误报未定义（真正的未定义仍会报）。

有 warning/error 时退出码为 1，干净文件输出"未发现问题"并退出 0（CI 可用）。

### 14.2 代码格式化（impor fmt / check-fmt）

`impor fmt 文件.impor [-o 输出] [--indent N] [--max-line N]` 规范化格式：

- 缩进宽度可配置：默认 4 空格（按词法 INDENT/DEDENT 深度重建）；v2.5 起读取
  `impor.toml` 的 `[fmt] indent_width`，CLI `--indent N` 可临时覆盖；
- 行内运算符两侧加空格（`a+b*2` → `a + b * 2`），逗号后加空格；
- 连续空行压缩为 1 个；行尾空白删除；字符串/注释内容原样保留；
- 首行 `important<<` 头部原样保留；
- `[fmt] max_line_length`：check-fmt 时对超长行输出提示（0=不检查，默认）。

`impor check-fmt 文件.impor` 只检查不修改，未格式化或存在超长行时退出码 1（CI 检查用）。

### 14.3 LSP 语言服务器（impor lsp）

基于 stdio 的 JSON-RPC 2.0 语言服务器，供编辑器集成：

- `textDocumentSync`：打开/编辑即推送 `publishDiagnostics`（语法错误 + 未定义变量，未使用变量/导入为 Info）；
- `definitionProvider`：变量/函数/类跳转定义（返回全部同名声明）；
- `hoverProvider`：悬停显示符号说明（函数签名/变量/类/导入）；
- `documentSymbolProvider`：文档大纲（顶层函数/类/变量/异常/导入）；
- `completionProvider`（v2.5）：自动补全——本文件符号、内建函数、关键字；
- `renameProvider`（v2.5）：符号重命名——按引用表同步修改同一文件内全部出现位置
  （未定义符号/内建/关键字拒绝）；
- `codeActionProvider`（v2.5）：QuickFix——删除未使用导入、给未使用变量加 `_` 前缀。
- 带头部标记（`important<<`）的文件，全部能力自动修正行号偏移（v2.5 修复）。

随附 VS Code 扩展 `vscode-impor/`：TextMate 语法高亮 + LSP 客户端（`python -m impor lsp` 启动），命令"Impor: 运行当前脚本 / 格式化当前脚本"。

### 14.4 包管理器（impor pkg）

源码包以 `impor.toml` 声明元信息（`[project] name/version`），安装后进入缓存 `~/.impor/pkg/`，运行时自动并入模块搜索路径：

| 命令 | 说明 |
|---|---|
| `impor pkg install <本地目录或git+URL>` | 安装源码包（可带 `name=约束`，违反已声明依赖则报错） |
| `impor pkg install name@版本` / `name=约束` | 从私有源安装指定版本 / 满足约束的最高版本 |
| `impor pkg install --frozen` | 严格按 `impor.lock` 还原并复核版本与完整内容哈希 |
| `impor pkg list` | 列出项目依赖与已安装包版本 |
| `impor pkg lock` | 生成/刷新 `impor.lock` v1.1（直接+传递依赖/来源/12 位 hash/`dir_sha256`/归档 sha256/`requires`） |
| `impor pkg lock --check` / `impor pkg check` | 校验锁文件、缓存版本与完整哈希，漂移返回 1 |
| `impor pkg upgrade [name]` | 私有源按约束取最高版本，git/本地源重新拉取 |
| `impor pkg registry` | 显示私有源 URL 与令牌是否配置（不打印令牌） |
| `impor pkg pack <目录> [-o 输出目录]` | 确定性打包 zip（固定时间戳/权限/排序，同内容同 sha256） |
| `impor pkg publish <目录或 zip>` | 上传归档并自动创建/更新索引；同版本需 `--force` |
| `impor pkg outdated` | 按锁文件来源检查约束内可升级的依赖 |
| `impor pkg prune` | 清理缓存中不可达的版本 |
| `impor pkg remove <name>` | 卸载并移除依赖声明 |

版本约束支持 `>=` `<=` `==` `!=` `>` `<` 与裸版本号（精确匹配）；git 源通过 `git clone --depth 1` 拉取。

**锁文件 v1.1**：`[lock]` 记录 `version` / `generated_by` / `generated_at` / `registry`；每个包记录 `version`、`source`、`hash`（目录 sha256 前 12 位）、`dir_sha256`（完整目录哈希）、`sha256`（归档哈希）、`requested`、`requires`、`installed_at`，缺包时标记 `installed = false`。`--frozen` 先按来源重装，再复核版本、12 位哈希与完整 `dir_sha256`，任何不一致立即报错——用于 CI 和复现构建。

**私有源**：`impor.toml` 的 `[registry]` 支持 `url` 与 `token_env`（默认 `IMPOR_TOKEN`），也允许直接写 `token`（不建议提交）；环境变量 `IMPOR_REGISTRY` 覆盖 URL。索引为 `<url>/index.json`：

```json
{
  "packages": {
    "mylib": {
      "0.1.0": {"url": "mylib-0.1.0.zip", "sha256": "64 位十六进制"},
      "0.2.0": {"url": "mylib-0.2.0.zip", "sha256": "64 位十六进制"}
    }
  }
}
```

`packages[name]` 也兼容数组形式 `[{"version": "0.1.0", "url": "...", "sha256": "..."}]`。归档必须是 zip，`impor.toml` 位于 zip 根或唯一顶层目录；`sha256` 缺失即拒绝安装。HTTP(S) 源使用 `Authorization: Bearer <token>`；`file://` 或本地目录同样可作为离线私有源。下载后先校验归档 sha256 再解压，解压拒绝路径穿越，归档内包名/版本与索引不一致同样拒绝。来源串写为 `registry:<base>#<name>@<ver>`，`upgrade` 与 `--frozen` 据此回到同一私有源。

**发布（v4.1）**：`impor pkg pack` 生成确定性 zip——固定 `date_time`、文件权限与条目顺序，并排除所有 `.` 开头的目录（含 `.git`、`.impor/` 缓存）、`__pycache__`、`.pytest_cache`、`dist`、`node_modules`，跳过 `.pyc` / `.pyo` / `.zip` 文件，同内容必得同一 `sha256`。`impor pkg publish` 可直接接收目录（内部先 pack）或 `.zip`（读取包内 `impor.toml`），上传后读取现有 `index.json`、合并条目、回写 `url` 与 `sha256`；同一版本已存在时拒绝，需显式 `--force`。HTTP 源用 `PUT` 上传归档与索引并带 Bearer 令牌，`file://`/本地路径直接写文件并自动创建父目录；源端返回 401/403/405 时会提示检查 PUT 支持与 `IMPOR_TOKEN` 写权限。

**依赖冲突检测（v2.8）**：安装新包时，若该包自身 `[dependencies]` 声明的依赖与项目已有声明不一致（同名不同约束），`impor pkg install` 直接报错并指明来源：

```
impor pkg install ./mylib
# impor: ValueError: 依赖冲突：mylib 的依赖与项目现有声明不一致：
#   x（项目要求 >=1.0，而 mylib 要求 ==0.5）
```

### 14.5 单元测试（impor test，v2.8 / v4.2 隔离）

}
```

## 18. 源码位置、异常体系与作用域（v2.10 核心重构）

### 18.1 源码位置记录

每个 AST 节点携带三个位置字段（`AST` 基类）：

- `lineno`：行号（1 起）
- `col`：列号（1 起）
- `file`：源文件名

词法层的换行 token（NEWLINE）也带列号，行尾错误可精确定位。这是语法诊断、
调试器、LSP 的共同基础。

### 18.2 自定义异常体系

| 异常 | 说明 |
| --- | --- |
| `ImporSyntaxError` | 词法 / 语法错误。携带 `lineno/col/filename/hint`；继承 Python `SyntaxError`，旧的 `except SyntaxError` 捕获保持兼容。`hint` 为修复建议（如"检查括号是否闭合"） |
| `ImporRuntimeError` | 运行时错误统一包装。解释器捕获 Python 底层异常（ZeroDivisionError、TypeError 等）后包装为该类，携带脚本源码位置与原始 `cause`，**隐藏 Python 内部堆栈** |
| `ImporException` | 既有运行时异常基类（NameError、AttributeError、CallError 等），现亦携带 `col` |

CLI 渲染规则：`文件:行:列 + 源码行 + 波浪线 ^^^ + 修复建议`。
设环境变量 `IMPOR_DEBUG=1` 可查看完整调试栈（含 Python 内部细节）。

**编译产物（v2.11）**：`impor compile` 生成的 .py 内嵌行号映射与源码行，
运行报错同样输出 Impor 风格（源码片段 + 波浪线 + 提示），不泄露 Python 内部栈；
`IMPOR_DEBUG=1` 时打印完整 Traceback。变量读取、复合赋值、`new`、类继承、
`raise` 等路径的 NameError 自动补齐源码位置。

### 18.3 作用域规范

- `var x = v`：**声明局部变量**（当前作用域）。
- `set x = v`：**就近更新**——沿作用域链找到已存在的绑定并更新；
  若不存在则写入当前作用域。闭包内 `set` 可修改外层函数的局部变量（无需显式声明）。
- `nonlocal set x = v`：显式更新最近的外层局部变量（找不到报 `ScopeError`）。
- `global set x = v`：显式更新全局变量。
- 函数每次调用创建独立局部环境（`Env`），闭包通过定义时的外层环境捕获变量；
  脚本异常被 `catch` 捕获后解释器进程不受影响，可继续执行。

```python
func make_counter() {
    var n = 0
    func inc() { set n = n + 1 return n }   # set 就近更新：修改 make_counter 的 n
    return inc
}
var c = make_counter()
print(c())   # 1
print(c())   # 2
```

## 14. C 后端：原生编译与 C ABI（v3.9.0）

`impor build FILE.impor [-o OUT.exe]` 走「AST → C 源码 → tcc 原生编译」链路，产出**独立可执行文件**：运行不依赖 Python、不依赖 Impor 本体。**C 后端是唯一发布路径**；`impor run` / `repl` / `run-dbg` 只做开发期运行与调试，`impor compile`（Impor → Python）只做开发兼容，`imporc` 只做内部一致性探针。

```powershell
impor build examples\fib.impor      # → fib.exe
impor build demo.impor -o game.exe
./game.exe                          # 直接运行
```

### 14.1 C ABI 共享库（`--lib`）

```powershell
impor build --lib lib.impor -o lib.dll
```

同时产出 `lib.dll`、`lib.h`、`lib.def`。源码写法：

```impor
export func add(a: int, b: int) -> int {
    return a + b
}
```

- 只导出顶层 `export func`；`export 名字` / `export {名字,...}` 旧写法仍可用（不产生 C ABI 导出）。
- 参数与返回值必须显式标注 `int / float / bool / str / void / size_t / handle / ptr`；未标注、`?`、泛型、默认参数、变参、类方法、`async` 一律报错，不静默降级。
- 类型映射：`int → long long`、`float → double`、`bool → int`、`str → const char *`、`void → void`、`size_t → size_t`、`handle/ptr → void *`。`handle` / `ptr` 用于不透明句柄和结构体按指针传递，本版不做命名结构体的强类型指针。
- 导出符号统一加前缀：`add` → `impor_add`。头文件带 `extern "C"`，可被 C/C++ 直接包含。
- `str` 返回值由 DLL 新分配，调用方必须用 `impor_free_str(const char *)` 释放；传入 `NULL` 安全。头文件同时声明该释放函数，`.def` 导出表也包含它。
- 实测链路：`impor build --lib lib.impor -o lib.dll` → 随包 tcc `demo.c lib.dll -o demo.exe` → 输出 `add(2, 3) = 5`。示例见 `examples/c_abi/`。
- MinGW `gcc demo.c -L. -lx` 需要额外生成 `.dll.a` import library；本机无 gcc/dlltool，未实测，文档不把它写成已通过。MSVC `.lib` 因本机无 `cl/lib/link` 同样未实测。

- **编译器**：`impor/tcc/win32/tcc.exe`（TinyCC 0.9.27）随包分发；PATH 中有 tcc 时自动回退使用。

### 14.2 C 源码包（`--lib --c-source`，v3.9）

内置 tcc 只产 **32 位（i386）** 产物。需要 64 位 DLL 时，不内嵌 100MB+ 的 w64devkit，而是输出 C 源码包，由用户机器上的 `cl` 或 `gcc -m64` 编译：

```powershell
impor build --lib --c-source lib.impor -o out/
```

产出：

```text
out/lib.c            # Impor 生成的 C 源码（含运行时与 ABI 包装）
out/lib.h            # 与 --lib 相同的头文件
out/lib.def          # 导出定义
out/build_msvc.bat   # cl /nologo /LD lib.c /Fe:lib.dll /link /DEF:lib.def
out/build_gcc.bat    # gcc -shared -m64 -O2 lib.c -o lib.dll
```

- `lib.h` 不随位宽变化；`demo.c` 不改即可用 `cl demo.c lib.lib` 或 MinGW 链接。
- `--c-source` 生成的 `lib.c` **不包含 `main`**，纯库源码；`cli` 的普通 exe/`--lib` 仍生成 `main`。
- 本命令**只生成源码，不调用内置 tcc**；产物位宽由外部编译器决定。
- 内置 tcc 的 `build --lib` 结束会打印 `产物位宽：32 位(i386)`；`impor sys-check` 同时报告 `解释器位宽` 与 `产物位宽`。
- 本机没有 `cl/gcc`，x64 包已生成并用 tcc 做过 32 位自检；x64 编译需在装有工具链的机器上运行两个 `.bat`，文档不把它写成已实测。

### 14.3 FFI（C 后端，v3.9）

`ffi_open` / `ffi_call` 现在解释器与 C 后端都支持，语法不变：

```impor
var lib = ffi_open("msvcrt.dll")
print(ffi_call(lib, "strlen", ["abc"], "int", ["cstr"]))
```

- 允许清单：`.impor/ffi_allow.json` 的 `allow` 数组 + `IMPOR_FFI_ALLOW`（逗号或分号分隔，大小写不敏感）。C 后端在 **build 时**把清单烘焙成 `g_ffi_allow[]`，运行时不能扩展。
- C 后端参数编组：`int → long long`、`bool → int`、`float → double`、`cstr → const char *`；最多 8 个参数。
- 返回编组：`int` / `float` / `bool` / `cstr` / `void`；`cstr` 复制进 `Val`，不依赖原指针。
- C 后端不接受 `ptr` 参数，也不支持结构体/回调：只做“调用”，不是第二条 ABI。
- 未登记库、超过 8 参数、动态 `argtypes` 都在 **编译期** 报错（exit 3），不生成运行时才崩的弱类型调用。
- 32 位限制：内置 tcc 产物只能加载 32 位 DLL；64 位消费方请先按 14.2 生成 x64 DLL。
- **三端位宽差异**：`impor run` 的宿主是 Python 解释器（本机 64 位），`impor build` 的默认产物是 32 位；同一个脚本 `run` 能加载的库与 `build` 能加载的库可能不同。加载前会读 PE `Machine` 字段，位宽不匹配时抛 `FFIArchError` 并给出中文原因，不再套成 `FFIError` 签名不匹配。
- 解释器加载 `msvcrt.dll` 这类系统库时仍按脚本目录解析相对路径；需要绝对路径时直接传 `C:\Windows\...`。

### 14.4 运行时与支持范围

- **值模型**：C 内嵌运行库 `Val`（null/int/float/str/bool/函数/数组/对象/字典/模块），类型保持：整数运算返回整数、浮点显式 `.0` 格式化（对齐 `str()`）、`%` 取正模、`and/or` 惰性求值并返回操作数本身、字符串 `+` 拼接、插值 `{expr}` 运行期求值。
- **已支持**：字面量、变量、算术/比较/逻辑、字符串拼接与插值、`if`/`elif`/`else`、`while`、`for ... range` / 数组与字典 `for-in`、顶层函数、嵌套函数/闭包（捕获外层变量、`nonlocal set`）、函数作为参数/返回值/变量、类与继承/`super`、`match`/`switch`、数组/字典下标读写、切片、属性访问、`enum`、`struct`、`try/catch/finally`（v3.8.4，setjmp 跳转栈）、模块导入（`import` / `from ... import`，见 8.8）、模块对象作为值（赋值/传参/比较/`type_of` 为 `module`）、`export`、管道 `|>`（v3.7.8 起降级为普通调用）；`print`/`input`/`inputstr`/`args` 与常用内建。
- **仍不支持（编译期友好报错）**：自定义异常、`defer`、两层以上嵌套函数与自递归闭包、嵌套类、Python 模块导入、`import_path`/`reload`/`open`/`readln`/`writeln`/`filemv`/`filecat` 等宿主相关内建。
- **双后端一致性**：单测强校验解释器与 `build` 产物对同一脚本输出逐字符一致（tests/test_v34.py）。
- AST 树遍历解释器完整保留：`impor run` 用于开发期全特性运行；`impor compile --exe` 仅作开发兼容；`impor build` 走原生 C，是唯一发布路径（exe / `--lib` DLL）。三者共享同一 AST。

## 19. 宽容语法层（v3.4）

目标：**同一意图允许多种写法，常见笔误不再让整份文件解析失败**。所有新写法都在词法/文法层**降级成既有 AST 节点**，因此解释器、Python 转译、C 后端（含 `impor build` 独立 exe）行为一致，关键字总量仍是 120，语义零变化。

### 19.1 语句写法

| 写法 | 等价 | 说明 |
| --- | --- | --- |
| `print "hi"` / `print a, b` | `print("hi")` / `print(a, b)` | `print` 可省略括号 |
| `var a = 1; var b = 2` | 逐行两条语句 | `;` 是语句分隔符，多余分号直接忽略 |
| `if x: a(); b()` | 块内两条语句 | 单行块体支持 `;` 分隔 |
| `var x: int = 5` | `var x = 5` | 类型注解只作提示，解析后丢弃 |
| `var x` | `var x = none` | 初始化可省略 |
| `const P: int` | `const P = none` | 同上 |
| `x := 1` | `x = 1` | `:=` 是 `=` 的别名 |
| `x++` / `x--` / `++x` / `--x` | `x += 1` 等 | 也可用于 `arr[i]++` / `obj.n--` |
| `a && b` / `a \|\| b` / `a <> b` | `a and b` / `a or b` / `a != b` | C 风格逻辑与不等号 |

### 19.2 块引导与条件

```impor
if x > 0 then { ... }        # then 可代替冒号
if x > 0 则 { ... }          # 中文同样有效
unless x > 0 { ... }         # 等价 if not (x > 0)
```

`unless`/`除非` 是取反条件；`then`/`则` 只是块引导符，可省略。

### 19.3 循环

```impor
for i in 1..5 { ... }        # 闭区间 1,2,3,4,5（等价 range(1, 5 + 1)）
for each x in 表 { ... }     # for ... in 的显式形式
for x of 表 { ... }          # of 是 in 的别名

for i = 0; i < 3; i++ { ... }  # C 风格计数循环（等价 for i in range(0, 3)）
for j = 1; j <= 3; j++ { ... } # <= 含上界（等价 range(1, 3 + 1)）
for i = 3; i > 0; i-- { ... }  # 递减，不含 0：3,2,1
for j = 3; j >= 0; j-- { ... } # 递减，含下界：3,2,1,0
# 方向必须一致：i-- 配 < / <= 或 i++ 配 > / >= 会在解析期报错，避免死循环

do { ... } until i >= 3      # 先执行一次，再判断（C 风格 do-while）
do { ... } while i < 3       # 条件为真时继续
```

`do-until` 降级成“标志变量 + while”：块体只出现一次，`continue` 会重新判定条件，块内声明不会重复。

### 19.4 函数、类与调用

```impor
func 加 a, b { return a + b }        # 参数可省略括号
func add(a: int, b: int) -> int { }  # 参数/返回类型注解只作提示
class 乙 extends 甲 { }               # extends 与 class 乙(甲) 等价
var o = new 盒                        # new 可省略空括号
super.hi()                            # 等价 super().hi()
```

### 19.5 异常与括号内续行

```impor
try { ... } catch { ... }        # 不写异常变量也能捕
try { ... } catch (e) { ... }    # 变量可加括号
```

圆括号 / 方括号未闭合期间，换行与缩进不再产生语句边界：

```impor
var r = add(1,
            2)
var arr = [1,
           2,
           3]
```

### 19.6 中文关键字（v5.2 起已移除）

v5.2 删除了全部中文关键字与中文软别名（`如果` / `变量` / `打印` / `除非` 等）。这些词现在只按普通标识符处理，不再等价于英文关键字；既有中文写法的脚本需改为英文关键字。保留字集合为纯英文。

### 19.7 边界

- 类型注解与 `->` 返回类型：`run` / `compile` / `build` 前会做轻量静态检查（字面量赋值、函数返回类型）；不引入泛型、不做控制流收窄，解释器运行时仍按动态值执行。
- 参数默认值、变参、`yield`、推导式、`with` 尚未支持，且 v3.8.4 起会在编译期明确拒绝（默认参数/变参/`yield`/`with` 提示 v3.12 计划，推导式提示 v3.9 计划）；C 后端已支持 `try/catch/finally`，线程/原子仍未支持。
- `imporc`（自举编译器）仍按 v3.3 语法子集工作：用宽容写法写的脚本请走 `impor run` / `impor build` / `impor compile`。
- 语法仍然严格的部分：括号不配对、缺少 `}`、`match` 分支缺 `:` 等结构性错误照旧报错，并带行号/列号/提示。

## 20. 文档注释（v3.5）

从 v3.5 起，注释分成两类：`#` 是普通注释，`##` 是**文档注释**——文档与代码绑定，进符号表、进编辑器悬停、进 `impor doc`。

### 20.1 语法

```impor
## 计算两数之和
## 返回 a + b
func add(a, b) {
    return a + b
}
```

- 必须**整行**以 `##` 开头（允许行首缩进），`##` 之后的文字就是文档正文；
- 连续多行 `##` 合并成一段，保留换行；中间可以夹空行；
- 行尾的 `##`（`x = 1  ## 说明`）不算文档注释，仍是普通注释；
- 括号 / 方括号未闭合的续行内出现的 `##`，按普通注释处理。

### 20.2 绑定规则

文档注释只绑定**紧随其后**的第一条语句：

- `func` / `def` 函数（含类方法）
- `class` 类
- `exception` 异常类型
- `var` / `const` 变量（悬停可见）

被绑定后，文档文本挂在 AST 节点的 `doc` 属性上；三端（解释器、Python 转译、C 后端）按 `type(node)` 分发，**不读 `doc`**，因此执行语义与 v3.4 完全一致。`impor fmt` 会原样保留 `##` 行。

### 20.3 LSP 悬停

`textDocument/hover` 在原有的签名/类型说明之后追加文档注释（引用块形式）：

```text
函数 `add`

> 计算两数之和
> 返回 a + b
```

符号表（`impor.analysis.Symbol`）新增 `doc` 字段；跳转定义、改名、补全的行为不变。

### 20.4 impor doc

```text
impor doc FILE              # 打印到终端
impor doc FILE -o API.md    # 写文件（UTF-8，LF）
```

输出按「模块 → 函数 / 类 → 方法」组织，只有带 `##` 文档注释的符号才会出现；没有文档注释时输出一行提示。

### 20.5 lint --style 与唯一推荐写法表

```text
impor lint FILE             # 原有语义检查，行为不变
impor lint --style FILE     # 额外检查「不推荐写法」
```

`impor.toml` 也可开启：

```toml
[lint]
style = true
```

风格检查全部为 `[提示]` 级，**不影响退出码**，可被 `# impor-lint-ignore: style-print` 或 `[lint] disable` 抑制。

检查项与唯一推荐写法见独立文件 **`docs/写法规范.md`**（v3.5 起为唯一标准）。

### 20.6 边界

- `imporc`（自举编译器）按 v3.3 语法子集工作，不认 `##` 文档注释；带文档注释的脚本请走 `impor run` / `impor build`。
- 文档注释是纯文本，不解析 Markdown 结构，不做交叉引用检查。
- 悬停只显示作者写的原文，不自动补参数说明或类型。

## 21. 写法收敛（v3.5）

v3.4 的宽容语法保持可用，但**冻结**：不再新增同义写法，且统一降级为「兼容层」。

- 唯一标准：`docs/写法规范.md`（推荐写法表）
- 检查工具：`impor lint --style`
- 收敛范围：12 类同义写法（`print` 省括号、`;` 分隔、`then/则`、`unless/除非`、`each/of`、`..`、C 风格 `for`、`do..until`、`++/--`、`&&/||/<>`、`:=`、中文软别名）以及 `extends` / `new A` 省括号 / `catch` 省变量 / 参数省括号

不做的事：**不删除功能**，不改语法错误行为，不影响 v3.4 已有测试与示例；淘汰（真正删除写法）留到 v4 重新评估。


## 22. 诊断信息结构（v3.6）

语言宪法第 3 条：报错不输出晦涩内部代号，直接说清 **哪里 + 是什么问题 + 为什么不合法 + 修复建议**。

### 22.1 四段式

每条诊断固定回答四件事，顺序不可变：

| 段 | 含义 | 呈现方式 |
| --- | --- | --- |
| 哪里 | 文件 / 行 / 列 | 首行 `第N行 列M:`，其后是带行号槽的代码片段与波浪线 |
| 是什么 | 错误类别 + 具体信息 | 首行 `语法错误:` / `运行错误:` / `C 编译错误:` + 异常名 + 消息 |
| 为什么 | 这条规则为什么存在、为什么这里不合法 | 缩进一行 `为什么：…` |
| 修复 | 可执行的改法（不是「请检查代码」） | 缩进一行 `修复：…` |

```
impor: 运行错误: 第2行 列10: ZeroDivisionError: division by zero  · demo.impor
    （设 IMPOR_DEBUG=1 可查看完整调试栈）
  1 │ func div(a, b) {
  2 │     return a / b
    │          ^^^^^^^
  3 │ }
  为什么： 除数是 0，数学上没有定义，运行无法继续。
  修复： 在除法前判断除数（if b != 0 { ... }），或先检查数据来源是否可能为 0。
```

### 22.2 首行兼容

`语法错误: 第N行 列M: <消息>` 是 v2.8 起就存在的格式，v3.6 **不改首行**，只在后面追加段落。
脚本、CI、编辑器正则里已有的 `第N行` / `第N行 列M` 匹配继续有效。

### 22.3 颜色

- 自动：`sys.stderr.isatty()` 为真时上色；Windows 控制台自动开启 VT 处理。
- 强制开：`IMPOR_COLOR=always`（或 `1` / `true` / `yes` / `on`）。
- 强制关：`IMPOR_COLOR=never`（或 `0` / `false` / `no` / `off`）、或 `NO_COLOR=1`。
- 被管道 / 文件重定向捕获时输出**纯文本**，不把 ANSI 转义写进日志或测试断言。

### 22.4 各入口一致性

| 入口 | 使用方式 |
| --- | --- |
| `impor run` / `run-dbg` | 完整四段 + 上下文片段 |
| `impor check` / `lint` / `test` / `compile` | 完整四段；`lint` 的行首 `文件:行:列 [级别]` 保持机器可解析 |
| `impor repl` | 位置 + 为什么 + 修复（输入已回显，不重复片段） |
| LSP `publishDiagnostics` | `message` 内追加 `为什么：` / `修复：`，诊断位置不变 |
| 图形编辑器 | 首行错误 + `修复：` 一行（输出面板是纯文本控件） |

### 22.5 波浪线与上下文

- 上下文：出错行前 1 行、后 1 行（REPL / 模块错误按可用源码给）。
- 波浪线：从出错列开始，长度取该行剩余字符与 8 的较小值，至少 1 个 `^`。
- 对齐按**显示宽度**计算，中文 / 全角字符按 2 列，BOM 与控制字符按 0 列。

### 22.6 边界

- 知识库按异常名与消息模式匹配；自定义异常名未收录时输出通用兜底（不省略「为什么 / 修复」两段）。
- C 后端仍以 `/*@L<行号>*/` 标记回溯 Impor 行号，宏展开或跨行表达式可能定位到最近的上一处标记。
- 诊断文案是给人读的，不承诺逐字稳定；脚本解析请依赖 `第N行 列M` 与异常名。

### 22.7 统一错误码、源码片段与调用栈（v4.3）

运行错误首行统一为 `运行错误: 第N行: 异常名: 消息 [E100x]`，解释器 / C 后端 / imporc 使用同一套编号：

| 错误码 | 异常名 | 错误码 | 异常名 |
| --- | --- | --- | --- |
| E1001 | ZeroDivisionError | E1007 | AssertionError |
| E1002 | TypeError | E1008 | NameError |
| E1003 | IndexError | E1009 | ConstError |
| E1004 | KeyError | E1010 | ImportError |
| E1005 | ValueError | E1011 | RecursionError |
| E1006 | AttributeError | E1012 / E1013 | OverflowError / MemoryError |
| E1099 | 其他 / 运行时内部错误 |  |  |

未捕获的运行错误随后输出「为什么 / 修复」、出错源码行与 `^` 定位，再追加调用栈，自顶向下、`->` 指向最内层：

```
运行错误: 第3行: ZeroDivisionError: division by zero [E1001]
  为什么： 除数是 0，数学上没有定义，运行无法继续。
  修复： 在除法前判断除数（if b != 0 { ... }），或先检查数据来源是否可能为 0。
  3 │     return 10 / x
    │ ^
调用栈（自顶向下）:
 -> f（第4行）
```

C 后端把源码行编译进独立 exe（`g_src_lines`），脱离 Python 仍能显示片段；imporc 产物复用同一运行时。
imporc 直接函数调用记录真实源码行，不再恒为 0。`impor explain E1001` 可单独查看错误原因、修法与最小示例。
`try/catch` 捕获到的异常不打印调用栈，进程正常继续。
