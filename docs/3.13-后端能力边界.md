# 后端能力边界（3.13.0）

Impor 有三个执行路径，**不是同一份语义承诺**。

| 能力 | 解释器 `impor run` | Python 转译 `impor compile` | C 后端 `impor build` |
|---|---|---|---|
| 整数 | Python 大整数 | Python 大整数 | int64，溢出报错 |
| 自定义异常 | 支持 | 支持 | 支持（v4.1 修订起；catch 类型不匹配会外抛到外层 try） |
| `try/catch/finally` | 支持 | 支持 | 支持（含类型化 catch、finally 与重新抛出） |
| 闭包 / 嵌套函数 | 支持 | 支持 | 部分支持；两层以上或自递归闭包拒绝 |
| 线程 / async | 无 | 无 | 无 |
| 默认参数 / 变参 / yield | 拒绝 | 拒绝 | 拒绝 |
| 产物 | 依赖 Python | 依赖 Python + impor 运行时 | 独立 exe / DLL（tcc 32 位） |
| 定位 | **唯一语义定义 / 默认运行方式** | 开发兼容 | **语法子集**，用于脱离 Python 分发；不支持即编译期拒绝 |

## 发布口径

- 默认运行与分发：解释器 + `ImporPortable.exe`。
- C 后端是语法子集，不是“唯一发布通道”，也不承诺与解释器逐位等价。
- 同一个脚本要跨后端运行，必须让数值留在 int64 范围内（快路径溢出会报错中止，可用 `--no-fast` 换回任意精度）。
- `build` 默认走数值快路径（纯整数子集 + 64 位溢出检查），失败自动回落完整 Val 值模型；`--fast`/`--no-fast` 可强制指定。

## 为什么不在 3.13 补齐

把 C 后端的大整数、自定义异常、完整闭包补齐，工作量远大于一个补丁版本；在 50 分钟窗口里硬做只会引入新回归。3.13 选择**把边界写清楚**，而不是继续用“唯一发布通道”掩盖差异。
