# Impor 语言 3.2.1：带载荷 ADT、async/await、三端对齐与安全边界

本版目标不是“再加几个语法糖”，而是把最容易让用户踩坑的三件事收敛：

1. 错误/结果能带数据（不是只有整数枚举）。
2. 异步有最小可用模型，并且解释器与编译产物状态一致。
3. 解释器能跑的 JSON / 正则 / lambda，C 后端也能跑。

---

## 1. 带载荷 ADT 与穷尽 match

```impor
enum Result {
    Ok(value)
    Err(message)
}

func make(n) {
    if n < 0 {
        return Result.Err("neg")
    }
    return Result.Ok(n * 2)
}

func main() {
    match make(5)
        case Result.Ok(v)
            print(v)
        case Result.Err(e)
            print(e)
}
```

语义：

- `enum` 成员可带一个或多个字段：`Ok(value)`、`Point(x, y)`。
- 构造：`Result.Ok(41)`。运行时值是 tagged dict：`{"__adt": "Result.Ok", "value": 41}`。
- 模式：`case Result.Ok(v)` 按字段名绑定；`_` 是通配；字段个数不符在解析/检查期报错。
- 穷尽性：无 `else` / `_` 的 `match` 必须覆盖该类型全部 tag，否则报 `match-exhaustive`。
- 兼容：无载荷 enum 仍是整数常量，旧代码不受影响。

写法提示：缩进式 `match x` + 换行 `case` 最稳；`case X { ... }` 在函数连续语句中容易触发“期望 OP”，本版未改该解析行为。

## 2. async / await / 最小任务

```impor
async func work(n) {
    return n * 2
}

func main() {
    t1 = work(3)
    print(task_status(t1))      # done
    print(run_tasks([t1, work(4)]))  # [6, 8]
    print(await work(7))        # 14
}
```

模型（刻意保守）：

- 单线程、无抢占、无事件循环。
- 解释器中 `async` 调用立即求值并包成 `Task`，`task_status` 返回 `done`，`await` 解包，`run_tasks` 顺序收集结果。
- C 后端没有任务对象，async 等同同步求值；`task_status` 恒 `done`，`run_tasks` 原样返回数组。
- 因此三端状态与结果一致；代价是没有真正的并发/挂起。需要并发时应等后续任务调度器，而不是假设 `async` 会并行。

## 3. 三端一致性：JSON / 正则 / lambda

解释器与 C 后端都已支持：

| 能力 | 函数/语法 | 说明 |
| --- | --- | --- |
| JSON 编码 | `json_encode(v)` | 对象键按插入顺序，布尔输出 `true/false`，字符串转义 |
| JSON 解码 | `json_decode(s)` | 支持转义、`\uXXXX`（BMP）、整数/小数/指数 |
| 正则匹配 | `regex_match(s, p)` | `^ $ . * + ? \d \w \s`、字符类 `[abc]` / `[a-z]` / `[^...]` |
| 正则查找 | `regex_find(s, p)` | 返回全部匹配数组 |
| 正则替换 | `regex_replace(s, p, r)` | 全局替换；无捕获组与反斜杠回溯 |
| 匿名函数 | `lambda(x): x * 2` | C 端为无捕获静态函数；捕获外层局部尚未支持 |

注意：Impor 字符串里的 `{...}` 会插值，写 JSON 字面量请用 raw string：

```impor
print(json_decode(r'{"x": 2}')["x"])
```

## 4. 跨文件访问控制

模块顶层可写可见性：

```impor
# _t_mod_priv.impor
visibility private func secret() {
    return 42
}

func visible() {
    return 8
}
```

```impor
import _t_mod_priv
print(_t_mod_priv.visible())   # 8
print(_t_mod_priv.secret())    # AccessError [E1099]
```

规则：

- `private`：仅本文件可访问；跨文件 `AttrGet` 与 `from ... import` 都拒绝。
- `protected`：模块内与“同包”访问保留；跨包默认拒绝。
- 报错：`AccessError: secret 是模块 _t_mod_priv 的 private 符号，不能跨文件访问 [E1099]`。
- 诊断：问题面板右键「解释诊断」会给“为什么 / 怎么修”，并可直接 Quick Fix。

## 5. FFI：默认拒绝的原生调用

```impor
var h = ffi_open("C:/Windows/System32/kernel32.dll")
var t = ffi_call(h, "GetTickCount", [], "int")
print(type(t))   # int
```

安全策略：

- 默认不允许任何原生库。允许清单来自环境变量 `IMPOR_FFI_ALLOW`（逗号分隔 DLL 文件名）或向上查找的 `.impor/ffi_allow.json`：

```json
{ "allow": ["kernel32.dll", "user32.dll"] }
```

- 只支持 `int/float/str/bool` 参数与返回值，最多 8 个参数；不做指针、数组、结构体，避免脚本获得任意内存读写。
- C 后端与自举不支持 FFI：编译产物会报未定义函数。这是明确边界，不是 bug。

## 6. 诊断：每条错误都有“为什么 / 怎么修”

问题面板选中一条诊断后右键：

- 解释诊断：弹出“为什么 / 怎么修”两段，并带「快速修复当前行」按钮。
- 快速修复当前行 / 批量修复本文件 / 跳到问题。

安全类诊断已内置：

- `AccessError`：模块顶层 `private` 只在本文件可见；修复方式是改 `public` 或提供公开转发函数。
- 其他规则沿用分析器 + 类型检查 + 样式 lint；每条都尽量给出可执行修复。

## 7. 三端边界（诚实声明）

| 能力 | 解释器 | C 后端 | 自举 `imporc` |
| --- | --- | --- | --- |
| 带载荷 ADT / match | ✅ | ✅ | ❌（子集） |
| async / await / run_tasks | ✅ | ✅（同步） | ❌ |
| JSON / 正则 / lambda | ✅ | ✅ | ❌ |
| 跨文件 private/protected | ✅ | 静态检查部分 | ❌ |
| FFI | ✅（白名单） | ❌ | ❌ |

自举编译器 `bootstrap/imporc.impor` 仍是“C 后端子集”，版本号已标 3.2.1 但明确输出“子集模式”。这是本版唯一没有闭环的一致性问题，文档不掩饰。
