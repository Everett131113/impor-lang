# Impor 3.2.1 安全模型：能防什么、不能防什么

“最高的安全性”在桌面应用里不能靠一句口号。本版把安全拆成可检查的应用层策略，并把做不到的部分写进威胁模型，避免虚假安全感。

## 1. 默认拒绝

| 能力 | 默认 | 如何开启 |
| --- | --- | --- |
| 插件写文件 | 拒绝 | `plugin_write_allow` / `IMPOR_PLUGIN_PERMISSIONS`，且路径必须在工作区 |
| 插件读文件 | 只读工作区与 Python 运行时 | 子进程 audit hook 阻断工作区外的 `open` / `listdir` |
| 插件网络 | 拒绝 | 权限清单声明 `net`；audit hook 阻断 `socket.connect` / `getaddrinfo` |
| 插件启动子进程 | 拒绝 | 权限清单声明 `process`；audit hook 阻断 `subprocess` / `os.system` |
| FFI 原生库 | 拒绝 | `IMPOR_FFI_ALLOW` 或 `.impor/ffi_allow.json` 的 `allow` 数组 |
| 大文件整文件加载 | 阈值以上转分块 | 用户显式选择“完整编辑” |

## 2. 路径围栏

`security.inside(root, path)` / `require_inside()`：

- 先 `os.path.realpath` 解析符号链接与 `..`，再 `os.path.commonpath` 比较。
- Windows 盘符不同、跨盘路径直接判越界。
- 所有插件写、编辑器保存、文件移动都走同一套围栏。

## 3. 原子写与完整性

`safe_write(path, content, root=...)`：

1. 同目录 `mkstemp` 创建唯一临时文件。
2. 写入、`flush`、`os.fsync`。
3. `os.replace` 原子替换。
4. 失败清理临时文件。

编辑器保存同样使用临时文件 + `os.replace`；断电/崩溃不会留下半截源文件。

供应链：`sha256_file()` / `verify_manifest()` 校验发布物与清单；当前只做完整性，不做签名。

## 4. 审计

`AuditLog(workspace).write(event, **fields)` 追加 JSONL 到 `.impor/audit.log`：

- `app.start`：版本、进程加固结果。
- `file.save`：路径、字节数、`atomic=True`。
- `plugin.write` / `plugin.write_current`：插件 ID、目标路径。

失败不静默：写不进去时返回 `False`，调用方仍继续业务，但安全中心会显示“暂无记录/读取失败”。

## 5. 进程加固

`harden_process()`：

- Unix：`RLIMIT_CORE=0`，关闭 core dump。
- 所有平台：清除 `PYTHONINSPECT`、`PYTHONSTARTUP`、`PYTHONPATH`，避免被环境变量注入启动代码。
- Windows 未设置 Job Object / AppContainer；这是残余风险。

## 6. 插件隔离

- 子进程 + JSON-RPC 代理；父进程持有权限判断。
- 子进程 `sys.addaudithook`：未声明 `write` 直接写文件、未声明 `net` 的 socket、未声明 `process` 的 `subprocess` / `os.system` 一律抛 `PermissionError`。
- 读范围限制在工作区、插件目录与 Python 运行时（`sys.prefix` / `sys.path`），工作区外 `open` / `listdir` / `scandir` 被阻断。
- 即使声明 `write`，直接写文件仍必须落在工作区内；越界写被阻断。
- 崩溃自动重启，最多 3 次；命令调用失败重试一次。
- 面板宿主显示权限清单与重启次数。
- 不是 OS 沙箱：子进程仍以当前用户身份运行；audit hook 只覆盖 Python 级事件，`ctypes` / 原生扩展可绕过。

## 7. 残余风险（必须知晓）

1. 同用户权限下的恶意代码可以绕过任何应用层检查。
2. 未启用 AppContainer / Job Object / 网络命名空间；插件写、网络、子进程由 Python audit hook 阻断，但 `ctypes` / 原生扩展调用可绕过。
3. FFI 仅限制参数类型与库白名单；被允许的库本身可能提供危险能力。
4. 更新通道依赖 HTTPS + SHA256 清单，未做代码签名验证。
5. 自举编译器与 C 后端不支持 FFI/部分新语法，安全策略只在解释器与编辑器生效。

## 8. 威胁模型摘要

- 资产：用户源码、工作区文件、编译器与发布物、插件进程、更新通道。
- 信任边界：编辑器主进程 ↔ 插件子进程；工作区 ↔ 系统其余路径；脚本 ↔ 原生库；发布物 ↔ 用户机器。
- 缓解：默认拒绝、路径围栏、原子写、权限清单、重启上限、审计、哈希、诊断。
- 残余：见上节。

需要更强边界时，应使用受限 Windows 账户、AppContainer、虚拟机或单独的构建机，而不是依赖编辑器的应用层策略。
