# Impor 系统编程基线

状态：**未就绪**。本文件只定义目标、顺序和验收，不把现有 C 后端当成系统编程能力。

## 现状

| 能力 | 状态 |
|---|---|
| C 后端 / 独立 exe | 有，TinyCC 转译 |
| 自举编译器 | 有，23 个一致性用例通过 |
| FFI 基础调用 | 有，int/float/str/bool，最多 8 参数 |
| FFI 指针 | 部分：解释器支持受控缓冲区 token；C 后端/自举未同步 |
| FFI 结构体 / 回调 | 无 |
| 稳定 C ABI / 头文件导出 | 无 |
| 自动内存管理 | 部分：运行时回收，不暴露手动 free；热路径规则未冻结 |
| 线程 / 原子 / 锁 | 无 |
| 直接 syscall / mmap | 无 |
| freestanding 运行时 | 无 |
| LLVM/Cranelift 后端 | 无 |

## 实施顺序

1. **FFI 指针与结构体**：指针 token 已进解释器；下一步结构体布局、回调，再同步 C 后端。
2. **稳定 C ABI**：导出函数、头文件生成、调用约定、错误码。
3. **自动内存与热路径**：保持运行时回收，不暴露 `free`；冻结零隐式分配规则。
4. **线程/原子/锁**：薄封装，明确内存序与错误模型。
5. **freestanding + 原生后端**：先脱 TinyCC 运行时，再评估 LLVM/Cranelift。

## 验收

- 用 Impor 写一个导出 `.dll/.so` 的库，C 程序能调用。
- 用 Impor 写一个无 GC 的 ring buffer，压测无泄漏。
- 两个线程通过原子/锁安全共享数据，TSAN 无报错。
- 编译一个不依赖 Python/TinyCC 运行时的 exe。
- 以上全部通过前，`impor sys-check` 的 `systems_ready` 必须保持 `NO`。
