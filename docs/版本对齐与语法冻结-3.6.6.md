# Impor 版本对齐与语法冻结（3.6.6）

日期：2026-11-15

## 一句话结论

**对外发布只有一条线：`3.6.6`。** `v6.0` / `v6.2` / `7.3.0` 是历史实验编号与内部路线/性能标签，不是本发布版本，也不作为安装包版本号。

## 三条编号的定位

| 编号 | 出现位置 | 定位 | 是否对外发布 |
|---|---|---|---|
| 3.6.6 | 源码、`pyproject.toml`、VSIX、桌面 ZIP、快捷方式 | 当前教学稳定线；语法已冻结 | 是 |
| v6.0 | `docs/路线图-v6.0.md` | 早期内部路线图，部分条目已并入 3.6.x | 否 |
| v6.2 | `docs/性能报告-v6.2.md` | 早期内部性能编号，仅用于报告对照 | 否 |
| 7.3.0 | `_backup/`、`vscode-impor/` 历史包 | 历史实验构建，已归档，不参与发布 | 否 |

## 版本规则（从 3.6.6 起生效）

1. `Impor.py` 的 `__version__` 是唯一运行时真源；其他文件只能与它一致。
2. 对外发布包只允许 `3.6.6` 形态；内部路线/性能报告不得占用“对外版本号”。
3. 语法冻结在 `3.6.6`：新增语法必须同时更新三端能力矩阵，并在 C 后端与自举端给出“支持”或“明确拒绝”，不允许静默通过。
4. 历史 `v6.x` / `7.3.0` 文档只作历史记录，读者不应按这些编号找安装包。

## 本次对齐动作

- `Impor.py version` 增加发布线说明：`3.6.6（教学稳定线，语法已冻结；v6.x / 7.3.0 为历史实验线）`。
- `VERSION` 文件写入 `3.6.6`。
- `docs/版本对齐与语法冻结-3.6.6.md`（本文件）与 `docs/三端能力矩阵-3.6.6.md` 成为发布口径。
- `docs/路线图-v6.0.md`、`docs/性能报告-v6.1.md`、`docs/性能报告-v6.2.md` 顶部加“历史内部文档”横幅，避免被当成发布版本。
- `_backup/` 增加归档说明；7.3.0 包不再作为发布候选。
