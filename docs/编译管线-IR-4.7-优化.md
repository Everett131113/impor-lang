# IR 优化（4.7.0）

4.6.0 的 IR 是「忠实降级、零优化」：AST 一旦降到 IR，指令就一条对一条地翻成 C 或解释执行，中间没有任何化简。
4.7.0 在 IR 上补了三个**可证明安全**的 pass（`impor/irop.py`），目标不是把程序跑快，而是证明这条管线里确实有一个优化器在起作用。

## 为什么在 IR 上做，不在 AST 上做

AST 的求值顺序里藏着副作用：`f() + g()` 谁先跑、`a[i] += 1` 里的下标求值几次，都不是树结构本身能看出来的。在 AST 上折叠或删代码，很容易把一个「有副作用但结果没用」的调用删掉。
IR 是三地址码，每条指令的读集合（`_srcs`）和写集合（`_defined`）都是显式的，副作用只发生在特定指令（`CALL` / `PRINT` / 算术 / `RAISE` / `SETINDEX`）上。所以优化放在 IR 层，判断「这条指令能不能删、能不能前移」是有依据的。

## 三项 pass

### 1. 常量折叠（`_fold`）

- `BINOP dst, op, Lit, Lit` → `CONST dst, 计算结果`，单条指令替换两条。
- 只在**结果能落在 int64 内**时折叠；溢出、除零、模零一律不折，原样留给运行时 E1012 —— 折叠不能改变错误行为。
- `**` 的指数大于 4096 不折（避免在编译期算出一个天文数字）。
- 字符串 `+` 允许折叠（纯常量拼接无副作用）。
- `JUMP_IF_FALSE Lit, L`：真值已知时，恒真直接删掉这条跳转，恒假改写成无条件 `JUMP L`。

### 2. 死代码消除（`_dead_body`）

- 只删两类：**目的量在整个函数里从未被读**的 `CONST` 与 `MOVE`。这两类不抛错、无副作用，删掉不影响任何可观察行为。
- 算术（`BINOP`）即使结果没人用也**不删**：它可能抛溢出或除零，删了就把一个本该报错的程序变绿了。
- 顺带删「`JUMP` 到下一条 `LABEL`」的空跳转（`OptStats.jumps`）。

### 3. 循环不变量外提（`_hoist_body`）

- 识别回边：`LABEL L ... JUMP L` 之间的区间就是一个循环体。
- 把区间内「读一个**循环内从未被写**的名字」的 `LOAD`，以及单定义的 `CONST`，提到 `LABEL L` 之前。
- 只处理**互不重叠**的循环区间（`_outer_only`），嵌套循环时不会因为删除指令导致下标错位；内层循环留给下一轮，不做激进的多层外提。
- 外提的是「读」，不是「写」：`s = s + base` 里 `s` 每轮都被 `STORE update` 写，所以 `LOAD s` 不满足条件；`base` 满足，被外提。

## 接线位置

- `impor/ir.py` 的 `evaluate()` 开头调一次 `optimize_module`；
- `impor/cir.py` 的 `to_c()` 开头调一次；
- `impor/cli.py` 的 `ir` 命令在 `lower_ast` 之后优化一次，把统计存进 `opt_stats`。

`optimize_module` 幂等：重复调用不会重复折叠（`CONST` 已折叠，没有可折的 `BINOP`）。

因为解释器路径和 IR→C 路径走的是**同一份优化结果**，两边等价不需要额外证明——由三路对拍兜住。

## 怎么用

```powershell
python Impor.py ir examples\grade.impor --stats
```

输出末尾多一行：

```
== 优化 ==
折叠 2 / 删死代码 1 / 外提不变量 1 / 简化跳转 0（指令 23 → 22）
```

目前没有「关闭优化」的开关：三项 pass 都不改语义，关掉只会让产物更差。

## 实测

| 用例 | 内容 | 结果 |
| --- | --- | --- |
| `ir_cf.impor` | `1 + 2 * 3`、一个只写不读的变量、循环内 `+ 2` | `CONST t2, 7`；折叠 2 / 删死 1；指令 23 → 22；输出 `7 / 30 / 999` 与解释器一致 |
| `ir_hoist.impor` | `for` 里读循环外 `base` | `LOAD t5, base` 提到 `L_for_cond_1` 之前；外提 1；输出 `50` 与解释器一致 |
| 全量示例（60 个，跳过 6 个交互） | 解释器 vs `ir --build` 产物逐字节对拍 | **一致 50 / 拒绝 6 / 构建失败 2 / 非确定跳过 2 / 不一致 0** |

「非确定跳过」是两个本身就不确定的示例：`demo_38_dice.impor`（随机种子取自时间）、`icon_demo.impor`（宽度依赖终端）。它们单列成 `nondet` 计数，既不混进「不一致」，也不静默丢弃。

## 未做

- 不做跨基本块/跨分支的全局活跃变量分析（现在的「从未被读」只在单函数线性扫描里判定，够用但保守）。
- 不做循环展开、向量化、强度削减（`i * 4` → `i << 2`）。
- 不做「把结果没人用的算术改成检查版之外的形式」——宁可少优化，也不改错误行为。
- 外提只做一层，不处理嵌套循环的外层不变量。
