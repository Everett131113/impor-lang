# 阶段二：标准库、服务与包生态

## 目标

让开发者不离开 Impor 就能写一个能部署、能观测、能升级的后端服务。

## 标准库优先级

| 优先级 | 模块 | 验收 |
|---|---|---|
| P0 | `net/http`、`json`、`log`、`config`、`time`、`fs` | 能写一个健康检查 + JSON API |
| P0 | `sql` + SQLite/Postgres/MySQL 驱动 | 能连接、查询、事务、连接池 |
| P1 | `tls`、`crypto`、`regex`、`compress` | 能处理 HTTPS 与常见编解码 |
| P1 | `test`、`bench`、`metrics` | CI 可跑、可压测、可观测 |
| P2 | `image`、`cli`、`template` | 常用工具链 |

## 包生态

- 中央注册表：命名空间、semver、锁文件、私有源。
- 安全：签名、审计、撤回、依赖图、许可证检查。
- 兼容：版本约束、弃用期、迁移指南。
- 质量门槛：每个官方库必须有测试、基准、文档、维护者。

## 验收

- 用 Impor 写一个真实 CRUD 服务，包含迁移、连接池、结构化日志、指标、健康检查、优雅退出。
- 用 Impor 写一个 CLI，能打包为单文件。
- 至少 20 个常用库可用，且有版本与安全记录。

## 当前状态

部分完成：已有 `pkg` 管理器、LSP、测试、格式化、lint、JSON/正则等能力；缺 HTTP/TLS/SQL/连接池/迁移/指标/中央注册表。  
在 P0 标准库与注册表完成前，生产后端只能走 Python 互操作作为过渡方案。
