# 阶段一：原生后端与内存模型

## 目标

让 Impor 生成的原生二进制达到“可部署”的最低标准，而不是只做教学演示。

## 必须完成

1. **代码生成后端**：LLVM 或 Cranelift，至少支持 `-O0/-O2`、调试信息、Windows/Linux x64。
2. **内存模型（3.6.1 定稿）**：系统层采用**自动管理**，由运行时负责 GC/作用域回收；语言层不暴露 `malloc/free`，也不要求用户手写释放。热路径仍要保证无隐式分配，并允许库作者使用内部 arena，但 arena 不作为用户可见 API。
3. **C ABI**：基本类型、结构体布局、回调、共享库导出、头文件生成。
4. **系统能力**：文件、进程、socket、线程、原子、时间、动态库、信号、环境变量。
5. **错误模型**：异常/错误码在原生后端的统一表示，不泄露 Python 栈。
6. **一致性**：解释器与原生后端过同一套 conformance，差异必须有白名单与原因。

## 验收

- 编译一个 CLI、一个 TCP 服务、一个 C 可调用的共享库。
- 热路径无隐藏分配，基准数据可复现。
- 交叉编译产物在干净机器上可直接运行。
- 崩溃有符号化栈，不出现“未知地址”。
