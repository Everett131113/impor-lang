# 阶段三：治理与发布

## 目标

让 5–10 人团队能长期维护同一套语言与工具链，而不靠某一个人的记忆。

## 必须完成

1. **规范冻结**：语言规范与实现分离；每个语法点有编号与测试。
2. **RFC**：破坏性变更必须走 RFC，包含迁移方案与弃用期。
3. **版本策略**：`主版本=破坏性`、`次版本=新增`、`修订=修复`；维护 LTS。
4. **CI 门禁**：`impor release-check --full` 必须通过；三端 conformance 不允许无声降级。
5. **发布工程**：可复现构建、校验和、SBOM、回滚包。
6. **安全**：`SECURITY.md`、私密报告渠道、CVE/公告流程、依赖审计。
7. **协作**：`CODEOWNERS`、PR 模板、代码风格、文档责任。

## 验收

- 新成员按 `CONTRIBUTING.md` 能在一天内跑通测试与打包。
- 一次破坏性变更走完 RFC、弃用期与迁移指南。
- 发布包有校验和、SBOM 与回滚说明。
- 安全问题有响应时限与公告记录。

## 当前状态

基线完成：`release-check` 命令、`SECURITY.md`、`CONTRIBUTING.md`、`CODEOWNERS`、本路线文档。  
未完成：LTS、SBOM、可复现构建、CVE 流程、正式 RFC 仓库与 PR 模板。
