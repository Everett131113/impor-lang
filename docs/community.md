# 社区入口（第 5 层）

只在有真实用户之后才扩社区。当前阶段的目标是 **1000 个真实用户 + 10 个真实项目**，
不是“先建一个空房间”。

## 现在开放的入口

| 用途 | 入口 | 什么时候用 |
|---|---|---|
| 报 bug / 提功能 | GitHub Issues（用模板） | 能写成“版本 + 系统 + 最小复现”的问题 |
| 不确定是不是 bug | GitHub Discussions | 用法问题、想法、想找人确认 |
| 看进度 | `CHANGELOG.md` + 每月例会记录 | 想知道下个月做什么 |

## 明确不做的

- 10 个真实用户之前不建 Discord / QQ 群 / 论坛：空房间比没有房间更劝退。
- 不做“许愿池”：没有场景和复现的功能建议，只记录不承诺。
- 不在公开仓库大规模宣传，直到“3 分钟成功”和“报错说人话”稳定。

## 每月例会（1 小时）

固定四段，不超时：

1. 上月交付：贴 `CHANGELOG` 链接，只讲用户能感知的变化（10 分钟）
2. 承诺兑现率：`docs/claims.md` 的 ✅ / ❌ 变化（10 分钟）
3. 真实用户问题：本月 issue 里最值得做的 3 条（25 分钟）
4. 下月计划：只写 3 件可验收的事（15 分钟）

记录模板见 `docs/meeting/2026-11.md`。第一次例会可以只有作者一个人，
但记录要公开，方便后来的人看到“这个项目是按月推进的”。

## 什么时候升级社区

满足任意两条再考虑：

- 连续两个月有外部 issue
- 有 3 个陌生项目在真实使用
- 同一个问题被不同人问过 3 次

到那时再建群，并且先把 `CONTRIBUTING.md` 和 `good first issue` 准备好。
