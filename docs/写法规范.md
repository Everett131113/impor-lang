# Impor (I++) 写法规范（3.11.0）

> 版本：v3.11.0
> 定位：面向人和工具的**推荐写法清单**，不是第二套语法标准。
> 事实基准：`docs/语言规范.md` 定义语法；`impor fmt` 决定格式化后的落地写法。本表与二者冲突时，以语言规范与实际 `impor fmt` 输出为准。
> 原则：同一意图只给一个推荐写法；其余写法能解析、能运行，但不再扩展。

## 0. 三条硬规则

1. **一种意图，一种写法**。下表「推荐写法」是默认答案；「兼容写法」只为旧工程可运行，不进入新代码。
2. **格式化即事实**。`impor fmt` 会把 `func` 改写为 `def`、把 `loop` 改写为 `while true`；推荐表按 fmt 的实际输出填写，不按历史文档想象。
3. **推荐写法零提示**。`impor lint --style` 对推荐写法不报风格提示；对兼容写法报 `[提示]` 并指向本表。

## 1. 语句与分隔

| 意图 | 推荐写法 | 兼容写法（不推荐） | 说明 |
| --- | --- | --- | --- |
| 多条语句 | 一行一条 | `a = 1; b = 2` | `;` 仅作兼容，不参与排版 |
| 语句块 | `{ ... }` | 冒号 + 缩进块 | 大括号块是标准形式；缩进块为旧工程兼容 |

## 2. 输出

| 意图 | 推荐写法 | 兼容写法（不推荐） |
| --- | --- | --- |
| 打印 | `print(a, b)` | `print a, b`（无括号） |
| 带退出码结束 | `exit(2)` | `exit`（等价 `exit(0)`） |

## 3. 变量与常量

| 意图 | 推荐写法 | 兼容写法（不推荐） | 说明 |
| --- | --- | --- | --- |
| 声明变量 | `var x = 1` | `let x = 1`、`local x = 1` | 三者语义等价，统一用 `var` |
| 赋值 | `set x = 1` | `x = 1`、`x := 1` | 裸赋值仍可用，fmt 也不会改写；团队统一用 `set` 更显式 |
| 只读常量 | `const N = 10` | `static` / `readonly` | 只读语义统一用 `const` |
| 类型注解 | `var x: int = 1`（可选） | 完全省略注解 | 注解参与 `run/compile/build` 前的静态检查；解释器运行时仍按动态值执行 |
| 省略初始化 | `var x = null` | `var x` | 显式写初值，避免“默认值是什么”的隐性规则 |

类型检查的边界：当前只检查可静态判定的字面量赋值与函数返回类型，不做泛型、不做控制流收窄。`run/compile/build` 遇到确定的不匹配会以退出码 2 中止；不会在运行时强制每个值都符合注解。

## 4. 条件

| 意图 | 推荐写法 | 兼容写法（不推荐） |
| --- | --- | --- |
| 条件分支 | `if x > 0 { ... } elseif y { ... } else { ... }` | `if x > 0 then { ... }` |
| 取反条件 | `if not x { ... }` | `unless x { ... }` |

## 5. 循环

| 意图 | 推荐写法 | 兼容写法（不推荐） | 说明 |
| --- | --- | --- | --- |
| 遍历集合 | `for x in 表 { ... }` | `for each x in 表`、`for x of 表` | 只有 `in` 一种连接词 |
| 计数循环 | `for i in range(0, n) { ... }` | `for i in 1..n`、`for i = 0; i < n; i++` | 区间语义由 `range` 显式表达 |
| 条件循环 | `while cond { ... }` | `do { ... } until cond`、`do { ... } while cond` | 需要“至少执行一次”时，先写一次再进 `while` |
| 无限循环 | `while true { ... }` | `loop { ... }` | `impor fmt` 会把 `loop` 改写为 `while true`；推荐直接用后者 |

## 6. 函数

| 意图 | 推荐写法 | 兼容写法（不推荐） |
| --- | --- | --- |
| 定义 | `def f(a, b) { ... }` | `func f(a, b)`、`func f a, b` |
| 返回 | `return x` | 函数末行裸表达式（自动返回其值） |
| 返回类型注解 | `def f(a) -> int { ... }`（可选） | 完全省略注解 |

> `func` 与 `def` 解析等价，但 `impor fmt` 统一输出 `def`。新代码从 `def` 开始，不要在同一文件混用。

## 7. 类与对象

| 意图 | 推荐写法 | 兼容写法（不推荐） |
| --- | --- | --- |
| 继承 | `class 子(父) { ... }` | `class 子 extends 父 { ... }` |
| 实例化 | `new A(x)` | `new A`（省空括号） |
| 调父类 | `super().m(x)` | `super.m(x)`（省括号） |

## 8. 异常

| 意图 | 推荐写法 | 兼容写法（不推荐） |
| --- | --- | --- |
| 捕获 | `catch e { ... }` / `catch Type e { ... }` | `catch { ... }`（省略变量） |

## 9. 运算符

| 意图 | 推荐写法 | 兼容写法（不推荐） |
| --- | --- | --- |
| 逻辑与/或/非 | `and` / `or` / `not` | `&&` / `||` / `!` |
| 不等 | `!=` | `<>` |
| 自增自减 | `x += 1` / `x -= 1` | `x++` / `x--` / `++x` / `--x` |
| 区间 | `range(a, b + 1)` | `a..b` |

## 10. 中文关键字

**现状：中文关键字已移除。** `如果` / `变量` / `打印` / `func` 的对应中文词不再翻译成关键字；在 3.8.1 中它们只是普通标识符，单独使用会得到 `NameError: 变量 函数 未定义` 一类的运行错误。中文**标识符**（变量名、函数名、类名）仍然完全可用，例如 `var 总数 = 0`。

历史说明：中文关键字是 v2.9 的差异化特性，v5.2 起移除；旧文档、旧 README 与旧示例若仍写“提供中文关键字”，以本节和实际运行结果为准。

## 11. 注释与文档

| 意图 | 推荐写法 | 说明 |
| --- | --- | --- |
| 普通注释 | `# 说明` | 不进符号表、不进 hover |
| 文档注释 | `## 说明`（紧邻声明上方，可多行） | 进符号表、进 LSP hover、进 `impor doc` |
| 多行注释 | `/* ... */` | 仅作说明，不绑定声明 |
| 抑制 lint | `# impor-lint-ignore` / `# impor-lint-ignore-file` | 见语言规范 |

文档注释绑定规则：

```impor
## 计算两数之和
## 返回 a + b
def add(a, b) {
    return a + b
}
```

- 必须**整行**以 `##` 开头（行首可有缩进），`##` 后内容即文档正文；
- 连续多行 `##` 合并为一段（保留换行），中间允许夹空行；
- 只绑定**紧随其后**的第一条语句（函数 / 类 / 方法 / 变量 / 异常类型）；
- 行尾 `##`（如 `x = 1  ## 说明`）不视为文档注释，仍是普通注释；
- 括号未闭合的续行内出现的 `##` 按普通注释处理。

## 12. 模块与导入

| 意图 | 推荐写法 | 兼容写法（不推荐） |
| --- | --- | --- |
| 导入模块 | `import math` | 隐式使用未导入的名字（lint 会报未定义） |
| 部分导入 | `from math import sqrt` | `import *`（除兼容旧工程外不要用） |
| 对外导出 | `export def f(...)` / `export var x` | 依赖“默认可被 import”的隐式导出 |

## 13. 检查方式

```text
impor lint FILE            # 语义检查（未定义/未使用/死代码/参数个数）
impor lint --style FILE    # 额外检查本表 + 可读性提示（命名/魔法数字/函数过长）
impor doc FILE -o API.md   # 从 ## 文档注释生成 API 文档
```

`impor.toml` 中也开启：

```toml
[lint]
style = true
```

可读性提示（全部为 `[提示]`，不影响退出码）：

| 规则 | 触发条件 | 建议 |
| --- | --- | --- |
| `style-naming` | 函数/类名或变量名只有 1 个字符（`i/j/k/x/y/n/m/t/e` 放行） | 用能表达用途的名字 |
| `style-magic-number` | 同一个非小整数在文件中出现 3 次以上 | 提取为 `const` 命名常量 |
| `style-long-function` | 函数超过 50 行或 30 条语句（可在 `impor.toml [lint]` 调 `max_function_lines` / `max_function_statements`） | 按职责拆成多个小函数 |
| `enum-exhaustive` | 对 enum 值做 `match` 但缺成员且无 `default` / `case _`（可用 `enum_exhaustive = false` 关闭） | 补全 case 或加兜底分支 |

## 14. 后端能力边界（3.8.4 实测）

发布路径只有 C 后端（`impor build`，出 exe 或 `--lib` 出 dll）。解释器只做开发期 `run/repl/run-dbg`；`impor compile` 只做开发兼容。

| 能力 | 解释器 / Python 转译 | C 后端 / imporc |
| --- | --- | --- |
| 类型注解 | 已检查字面量赋值与返回类型（编译入口） | 同左，仅 Python 转译路径 |
| `yield` / 生成器 | 未实现 | 未实现 |
| 列表/字典推导式 | 未实现 | 未实现 |
| 默认参数 / 变参 | 未实现 | 未实现 |
| `with` | 未实现 | 未实现 |
| `try/catch` | 已支持 | Python C 后端已支持（v3.8.4 `setjmp` 跳转栈）；imporc 子集仍拒绝 |
| 线程 / 原子操作 | 无语言级内建 | 无语言级内建 |
| 导出 `.dll` | 不适用 | 支持顶层 `export func` + 显式 `int/float/bool/str/void/size_t/handle/ptr`；字符串返回值用 `impor_free_str()` 释放；其他形态报错 |
| 读取命令行参数 | `args()` 可用 | `args()` 可用（3.8.1 起 main 注入 argc/argv） |

这张表是 v3.8.4 的交付边界，不是路线图承诺。未实现项不会被文档包装成“已支持”。
`yield` / `with` / 默认参数 / 变参 / 推导式在 v3.8.4 会在编译期明确拒绝（exit 2，提示 v3.9 计划），不再静默当 null 执行。
MinGW `gcc -L. -lx` 需要 `.dll.a` import library，本机无 gcc/dlltool，未实测；MSVC `.lib` 同样因本机无 `cl/lib/link` 未实测，不写成“已通过”。

## 15. 变更记录

- v3.8.4：语义诚实——`yield` / `with` / 默认参数 / 变参 / 推导式编译期明确拒绝；C 后端补 `try/catch/finally`（除零可捕获，`exit(7)` 返回 7）；`imporc` 版本字符串同步 3.8.4。
- v3.8.3：C ABI v2——新增 `impor_free_str`，类型映射补 `size_t` 与 `handle/ptr`（`void *`）；imporc 修复 BOM、单行 `{}` 块与失败退出码；PyQt6 缺失时内核预览烟测正确跳过。
- v3.8.2：C 后端定为唯一发布路径；新增 `export func` 与 `impor build --lib`（dll + h + def）；导出边界只支持显式标量类型。

- v3.8.1：以 `impor fmt` 的实际输出重写本表；`def` / `while true` 定为推荐写法，`func` / `loop` 降为兼容；中文关键字统一说明为已移除；类型注解从“只解析”改为编译入口检查；补后端能力边界表。
- v3.8.0：`impor lint --style` 增加命名 / 魔法数字 / 函数过长三条可读性提示；`impor fmt` 修正大括号块缩进。
- v3.5.0：建立本表；把 v3.4 的 12 类同义写法统一降级为「兼容层」。
