# Impor 编辑器 3.2.3：五项编辑器升级

本版只升级编辑器，语言、三端与安全策略沿用 3.2.2。五项全部进入 3.2.3，不拆版本。

## 1. 符号级语义高亮

旧版只有关键字、内建、字符串、数字、注释和启发式函数/类名着色，变量、参数、模块、字段无法区分。3.2.3 先做一遍轻量符号表，再按符号类别着色。

- `impor/editor.py` 顶部新增 `_SEM_DECL`、`_SEM_FOR`、`_SEM_IMPORT`、`_SEM_FROM`、`_SEM_FUNC` 与纯函数 `semantic_symbol_map(src)`。
- 映射优先级：参数 5 > 局部变量 4 > 函数 3 > 类/结构/异常 2 > 模块 1；同名符号后出现的高优先级声明覆盖低优先级。
- 支持 `func/def` 参数、`var/const/let/set`、`class/exception/struct`、`for`、`import`、`from ... import ... as ...`。
- `THEME` 三套主题新增 `sem_var`、`sem_param`、`sem_field`、`sem_module`；对应 Tk tag 加入 `_configure_tags()`。
- `highlight()` 在关键字/内建之后、启发式 `func/cls/decl` 之前应用：变量→`sem_var`、参数→`sem_param`、模块→`sem_module`、函数→`func`、类/结构→`cls`；`obj.field` 且非调用的字段→`sem_field`。
- `true/false/null/nil/self/this/super` 仍走原有 `sem` 分支。

实测（`_gui323.json`）：示例源码产生 `sem_var=5`、`sem_param=4`、`sem_module=1`、`func=3`、`cls=1`，符号表 8 项。

边界：字段按 `obj.field` 形式推断，尚未从 AST 精确提取字段声明；枚举成员暂与普通变量同色；同名符号跨函数共享同一类别，不做作用域隔离。

## 2. 异步防抖诊断

旧版每次修改后同步解析整文件，输入时主线程会被大文件拖住。3.2.3 把诊断放到后台线程，并用代次丢弃过期结果。

- `EditorPane` 新增 `_diag_job`、`_diag_gen`、`_diag_queue`、`_diag_thread`、`_diag_poll_job`、`_problem_marks`、`_lint_payload`。
- `_on_modified()` 在 90ms 高亮调度之后调用 `_schedule_diagnostics()`；300ms 防抖，受 `app.async_diagnostics` 开关控制。
- `_start_diagnostics()` 抓取当前文本、`strip_header`、计算 header offset，递增 `_diag_gen`，启动 daemon 线程；worker 只调用 `App._collect_lint(src, path)`，结果写入 `queue.Queue`，不跨线程碰 Tk。
- `_poll_diagnostics()` 在主线程每 150ms 排空队列，只应用最新 `gen` 的结果；线程存活或队列未空时继续轮询。
- `App._collect_lint` 是纯计算：`Parser(tokenize(...))`、`analyze()`、`style_lint()`、`typecheck.check_source()`，返回 `(issues, error)`。
- `App._apply_lint` 把结果写入 pane 自己的 `_problem_marks` 与 `_lint_payload`；只有当前 pane 才刷新问题面板与错误/警告计数。切换标签时 `select_pane` 重放该 pane 的诊断，面板不会串文件。
- `_lint_pane` 保留同步入口，保存/显式检查时调用，并递增代次作废在途异步结果。

实测（`_gui323.json`）：插入 `func broken(` 后 300ms 防抖触发，pane 收到 1 条错误标记，面板显示语法错误；当前 pane 切换后仍保留自己的标记。

边界：防抖后仍解析整文件，不是增量 AST；超大文件建议关闭“异步诊断”或等待解析；后台线程只做纯计算，插件/UI 操作不进入 worker。

## 3. 覆盖率行号栏内联

3.2.2 的覆盖率只在独立 Treeview 里看，编辑时看不到行状态。3.2.3 把覆盖率画进行号栏。

- `redraw_lineno()` 增加两段：诊断标记（错误红色下划线、警告黄色下划线，读取 pane 自己的 `_problem_marks`）与覆盖率条（`x=3..5`，绿色=命中、红色=可执行但未命中）。
- 覆盖率条仅在当前 pane 路径与 `app._coverage_target` 一致时显示。
- `App._coverage_exec`、`App._coverage_offset` 新增；异步 payload 从 `(path, snapshot)` 扩展为 `(path, snapshot, exec_lines, offset)`，`_poll_queue` 兼容旧三元组。
- worker 用 `strip_header` 后的正文计算可执行行；header 偏移随 payload 回传，行号栏与 Treeview 都按显示行号对齐。
- `show_coverage()` 对可执行行和命中行统一加 offset，修复 header 行导致的错位；新增“跳下一个未覆盖”按钮，`next_uncovered()` 定位到下一个未命中可执行行。

实测（`_gui323.json`）：带 header 的示例运行后 `_last_coverage` 有数据，`_coverage_exec=7` 行、`_coverage_offset=1`，行号栏出现覆盖率条；“跳下一个未覆盖”跳到第 2 行。

边界：只覆盖解释器路径，C 产物不产覆盖率；只显示当前文件；表达式不单独计行；折叠/虚拟滚动时只画可视行。

## 4. Git 三方合并编辑器

旧版冲突入口只能打开原文件看标记。3.2.3 提供 base / ours / theirs 三栏与逐块接受。

- `split_conflict_markers(text)` 支持 `merge` 与 `diff3` 标记；返回 `segments`（普通字符串或 hunk dict）与 `hunks`；未闭合标记按普通文本保留，避免保存丢内容。
- `git_conflicts()` 双击行为从“打开原文件”改为 `open_conflict_merge(path, repo_path)`。
- `App._git_merge_text(path)`：`git show :2/:1/:3` 取 ours/base/theirs，写临时文件后执行 `git merge-file -p --diff3 -L ours -L base -L theirs ours base theirs`；returncode 0/1 都接受（1 表示有冲突）。
- `open_conflict_merge`：1240×780 窗口；左侧冲突块列表；右侧 BASE / OURS / THEIRS 三栏只读 Text；下方合并结果预览。
- 逐 hunk 按钮：采用 OURS、采用 THEIRS、采用 BASE、保留双方；选择后列表标记“已解决”。
- 保存前检查未解决数量；全部解决后用 `Parser(tokenize(strip_header(text)))` 做语法校验，失败中止保存。
- 原子写回：先写 `path + ".impor-merge.tmp"`，再 `os.replace`。
- 两个保存入口：“保存工作区”和“保存并 git add”；后者执行 `git add -- repo_path`。
- 保存后刷新已打开 pane 内容、重置 modified 标记并重新高亮。
- 命令面板新增“Git 三方合并”入口。

实测：`_git323.json` 用临时 Git 仓库制造真实冲突，`_git_merge_text` 返回含 `<<<<<<< ours`、`||||||| base`、`=======`、`>>>>>>> theirs` 的 diff3 文本；`_gui323.json` 中合并窗口成功构建 10 个 Text 控件（三栏 + 预览 + 列表等）。

边界：依赖本机 git（`shutil.which` 或 `D:\Git\cmd\git.exe`）；只处理当前仓库内的路径；语法校验只保证能解析，不保证语义正确；保存并 git add 默认不提交。

## 5. 插件管理器

旧版插件只能靠项目设置或手放目录，启停/卸载/版本信息没有统一入口。3.2.3 增加本地插件管理器。

- `impor/studio_ext.py` 的 `PluginManager` 新增：
  - `home_root()` → `~/.impor_studio/plugins`。
  - `state_path()` → `~/.impor_studio/plugins_state.json`；`_read_state` / `_write_state`。
  - `is_enabled(path)` / `set_enabled(path, enabled)`。
  - `_iter_plugin_files(root)`：根级 `.py` + 一级子目录的 `plugin.py` / `main.py` / `__init__.py`，或子目录唯一 `.py`。
  - `discover()`：遍历 `roots()` 去重。
  - `meta(path)`：读取 `# impor-name`、`# impor-version`、`# impor-description`、`# impor-permissions`，也支持同目录 `plugin.json` 的 name/version/description。
  - `install_folder(src)`：单文件复制到 home root；文件夹复制为 `home/<name>`，重名追加时间戳；无插件文件则回滚并抛错。
  - `install_zip(zip_path)`：先做 zip 路径越界检查，再解压；单目录安装目录，根级 `.py` 直接复制到 home root。
  - `uninstall(path)`：只允许删除插件根内路径；单文件删文件，包内文件删其父目录。
  - `reload()`：shutdown 隔离进程、清空 `plugins/commands/panels/status_items/themes/formatters/errors`、重置 `_loaded` 后重新 `load()`。
- `load()` 改为基于 `discover()`，跳过 `is_enabled=False` 的插件。
- `editor.py` 新增 `App.show_plugin_manager()`：980×620 窗口；Treeview 列“状态 / 名称 / 版本 / 权限 / 路径”；按钮“安装文件夹、安装 ZIP、启用/禁用、重新加载、卸载、关闭”；详情区显示描述、读/写/网络/子进程权限、声明列表、路径；双击行切换启用状态；卸载前确认。
- 安装/卸载后自动 `reload()`，启停即时生效；命令面板新增“插件管理器”。

实测（`_gui323.json`）：临时插件目录安装后管理器列表 1 行，名称 `Demo323`、版本 `3.2.3`、权限 `read、write`；`tests/test_v323.py` 覆盖 install_folder / meta / 启停 / uninstall / install_zip / zip 路径穿越拒绝。

边界：只做本地文件夹 / ZIP 安装，不含在线市场；in-proc 插件无法真正卸载已导入模块，`reload()` 清空注册表后重新加载；隔离插件会 stop 后重启；安装文件夹会整包复制，可能带入无关文件。
