# Impor 编辑器 7.2.0

7.2.0 是编辑器体验批次，不改语言语法。以下功能全部在 `impor/editor.py` 与 `impor/studio_ext.py` 内实现。

## 1. 渐进式启动

- 默认先构建工具栏、活动栏、资源管理器、outline、标签与编辑区，`root` 先进入事件循环。
- splash 的停留时间改为 280 ms、淡出 120 ms；单击、Esc、空格可立即进入。
- 底部输出/终端/测试/调用图/内存/问题面板、会话恢复、插件、文件监听在首帧之后补齐。
- 关闭渐进式启动：设置环境变量 `IMPOR_NO_PROGRESSIVE=1`。
- 关闭 splash：设置 `IMPOR_NO_SPLASH=1`。

实测（本机 Python 3.11.5，`IMPOR_NO_SPLASH=1`）：

| 阶段 | 耗时 |
| --- | --- |
| `App(root)` 返回外壳 | 约 884 ms |
| 首次 `root.update()`（含底部面板补齐） | 约 642 ms |
| 真实窗口标题首次可见 | 约 1,220.8 ms |

7.1.0 的编辑器主窗实测约 5.9 s，因此 7.2.0 的外壳首帧明显提前；底部面板仍在后台补齐，不阻塞外壳。

## 2. 自动更新与回滚

- 启动 7 秒后静默读取 `site/update.json` 或 `IMPOR_UPDATE_URL`。
- 发现更高版本时只在状态栏显示「发现新版本 x · 点击更新」，不弹窗。
- 手动「检查更新」保留 SHA256 校验、`code --install-extension` 安装和旧 VSIX 回滚。
- 下载过程显示进度窗；安装成功后询问是否重载 VS Code 窗口。
- `code --command workbench.action.reloadWindow` 不是所有 VS Code CLI 版本都支持，失败时提示手动重启，不杀进程。
- 回滚范围仅 VSIX；启动壳和应用本体不参与自动回滚。

## 3. 项目级配置

路径：`<workspace>/.impor/settings.json`，UTF-8 无 BOM、LF、末尾换行，写入使用临时文件 + `os.replace`。

优先级：项目设置覆盖全局 `~/.impor_studio.json`。

支持的键：

```json
{
  "theme": "dark",
  "font_size": 11,
  "editor": {
    "indent": 4,
    "word_wrap": false,
    "minimap": true,
    "inlay_hints": true,
    "semantic_highlighting": true,
    "large_file_kb": 2000
  },
  "format": { "on_save": false },
  "autosave": true,
  "shell": { "profile": "cmd" },
  "tasks": {
    "run": "\"{python}\" -m impor run \"{file}\"",
    "build": "\"{python}\" -m impor build \"{file}\""
  },
  "plugins": ["D:/impor-plugins"]
}
```

- 设置对话框底部新增「保存到项目 .impor/settings.json（覆盖全局）」。
- 命令面板新增「项目设置 .impor/settings.json」，可在内置 JSON 编辑器中修改并立即应用。
- 切换工作区时重新读取项目设置并应用字号、缩进、换行、缩略图、inlay、语义高亮、大文件阈值、保存格式化、自动保存和主题。

## 4. 只读插件 API

插件搜索根：

1. `~/.impor_studio/plugins`
2. `<workspace>/.impor/plugins`
3. 项目设置 `plugins` 数组中的额外目录

只加载 `.py`，模块必须提供 `register(api)`。加载失败只记录到 `PluginManager.errors`，不阻塞编辑器启动。

API 暴露的读取方法：

| 方法 | 作用 |
| --- | --- |
| `current_text()` | 当前编辑器文本 |
| `current_path()` | 当前文件路径 |
| `read_file(path)` | 读取工作区文本文件 |
| `list_files(suffix)` | 列出工作区文件 |
| `toast(text)` | 浮层提示 |

注册方法：

| 方法 | 作用 |
| --- | --- |
| `register_command(title, callback, shortcut="")` | 命令面板命令 |
| `register_panel(title, builder)` | 左侧插件侧栏页；`builder(frame, api)` |
| `register_status_item(text, callback=None)` | 状态栏条目 |
| `register_theme(name, colors)` | 覆盖 `THEME` 的颜色字典 |
| `register_formatter(name, func)` | 文本格式化器，`func(text) -> str` |

示例：

```python
def register(api):
    api.register_command("统计行数", lambda: api.toast("%d 行" % len(api.current_text().splitlines())))

    def panel(frame, api):
        import tkinter as tk
        tk.Label(frame, text="插件面板", bg="#111820", fg="#d5dde8").pack()

    api.register_panel("示例", panel)
```

边界：API 表面不提供写文件或执行命令方法；插件是本地 Python，和编辑器同进程执行，不是进程隔离。只应安装可信插件。

## 5. Git 深度集成

Git 面板新增：

- **行级 blame**：对当前文件当前行执行 `git blame -L n,n --porcelain`，显示作者、短 SHA 和提交。
- **按 hunk 暂存**：`git diff --unified=0` 拆 hunk，选中后写入临时 `.patch`，执行 `git apply --cached --unidiff-zero`，只进 index 不提交。
- **冲突入口**：`git diff --name-only --diff-filter=U` 列出未合并文件，双击打开。编辑器原样显示冲突标记，由用户手动解决。
- 原有刷新、diff、分支查看/切换、初始化、暂存全部、提交保留。

所有命令固定 `git -C <workspace>`；工作区不是 Git 仓库时直接显示 Git 的 stderr。

## 6. 多终端与任务模板

- 「多终端标签」打开 Toplevel + Notebook，可新建多个持久 shell 标签，每个标签独立进程。
- profile 支持 `cmd`、`powershell`、`pwsh`，默认取项目设置 `shell.profile`。
- `Ctrl+C` 发送 terminate；关闭标签结束该 shell。
- 任务模板从项目设置 `tasks[kind]` 读取，支持 `{file}`、`{workspace}`、`{python}`、`{kind}`；没有模板时回退 `python -m impor <kind> <file>`。
- problem matcher 从任务输出抓 `file:line[:col]`，写入问题面板并累计错误数，去重。

## 7. 编辑器智能

- **inlay hints**：行号槽加宽到 92 px，`var/let/const/set` 行按字面量推断 `num/str/bool/arr/dict/func/obj`，仅对可视行绘制。
- **语义高亮**：`true/false/null/nil/self/this/super` 使用 `sem` 标签（青色加粗）；这是常量/自指词级语义，不是基于符号索引的全量语义着色。
- **括号着色**：`()[]{}` 四层颜色，原有能力保留。
- **sticky scroll**：编辑器顶部新增「作用域」吸顶条，跟随光标显示 `文件 › 类 › 函数`；面包屑保留。
- **大文件模式**：项目设置 `editor.large_file_kb` 控制打开确认阈值（默认 2000 KB）；大文件只对可视行 ±30 行着色，缩略图超过 6000 行跳过。

## 8. 可访问性

- 新增 **高对比主题**：纯黑底、白/黄前景、青色强调、白色边框；`dark → light → hc → dark` 循环。
- 键盘焦点快捷键：`Ctrl+1` 编辑器、`Ctrl+2` 资源管理器、`Ctrl+3` 底部命令条、`Ctrl+4` 问题面板、`Ctrl+5` 命令面板。
- 命令面板新增对应「键盘焦点：…」命令，全部有真实回调。
- 字号缩放沿用 `Ctrl+=` / `Ctrl+-`，范围 9–18，并写入全局或项目设置。

限制：Tkinter 没有完整的 Windows UIA 屏幕阅读器接口，7.2.0 只做到可见标签、键盘可达和高对比，不等于原生屏幕阅读器全量适配。
