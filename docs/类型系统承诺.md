# 类型系统承诺（4.7.1）

这份文档回答一个问题：**Impor 的类型标注到底保证了什么，不保证什么。**

4.7 之前的口径是「typecheck + 猜测 + strict 档」的混合体，用户学不会信任它。所以
这里不再描述实现，只给一张**可执行验证的承诺表**——每一行都写明「违反时会不会
拦下你」以及「拿什么命令复验」。

一句话版本：**Impor 的类型系统是「渐进检查 + 运行期动态值」**，不是静态类型系统，
也不是 HM。标注是实现者与编译器的约定，不是数学证明。

---

## 一、会拦住你的（ERROR，退出码非 0）

| 检查 | 触发条件 | 在哪一端 | 复验命令 |
|---|---|---|---|
| 语法/词法 | 写法不在语言内（如 `<<`、`**`、无 `var` 的裸赋值） | 解释器与 C 后端同一份 AST | `impor run x.impor` |
| 未声明变量 | 赋值给从未 `var` 声明的名字 | 同上 | `impor run x.impor` |
| 名字不存在 | 调用不存在的函数/读不存在的模块符号 | typecheck 门禁 | `impor check-types x.impor` |
| 实参与形参**显式冲突** | 把字符串传给标注为 `int` 的参数 | typecheck 门禁 | `impor check-types x.impor` |
| C 后端不支持 | 用了后端没实现的语法子集 | 构建期拒绝，不静默降级 | `impor build x.impor` |

这几条是硬的：`run` / `build` / `compile` 都先过同一个门禁，过不了就不执行。

## 二、只提醒、不拦你的（WARN）

4.7 新增的 `impor/semantic.py` 补了三类检查，默认 **WARN**；加 `--strict-types`
（或 `IMPOR_STRICT_TYPES=1`）才升 ERROR：

| 检查 | 抓什么 | 为什么默认不硬拦 |
|---|---|---|
| `arith-type` | `int + str`、`float - int` 这类混合算术 | 语言允许隐式数值提升，硬拦会打碎既有代码 |
| `int-range` | 字面量超出 int64（如 `2**63`） | 少数地方靠溢出回绕做位运算 |
| `missing-return` | 有返回标注但存在不返回的分支 | 控制流分析是保守近似，会误报 |

`--strict-types` 下这三类变 ERROR。**这是你唯一能拿到「标注被检查」的档位**；
不加它，等于标注只用于单态化和优化，不做语义约束。

复验：

```
impor check-types .                 # 全仓递归，默认 WARN
impor check-types x.impor --strict-types
echo %ERRORLEVEL%                   # strict 档下发现 WARN 即非 0
```

## 三、完全不保证的（这是 soundness 边界）

以下四件事**任何档位都不保证**，不要指望类型标注替你兜住：

1. **运行期类型**。值模型是 `Val` 装箱（null/int/float/str/bool/数组/对象/函数），
   类型在运行期才存在。把字符串当数字用，只有真正执行到那一步才报 E1005。
2. **无返回标注函数的返回类型**。没有 `-> int` 的函数，其返回类型是**猜的**
   （父类 typecheck 早年默认猜 int）。4.7 的 `semantic._strict_type` 因此只信
   「字面量 / 本函数带标注的变量 / 带返回标注的调用」，其余一律 `?` 并跳过——
   宁可不报，也不报假警告。
3. **泛型/擦除路径**。单态化只对「实参是字面量（或标注自洽）」的调用点生成原生
   实例；其余回退 `static Val f(Val,...)` 擦除版，那条路径上不做元素类型检查。
4. **整数溢出语义**。`int` 是 int64 单一口径。C 后端在 `+ - *` 上插入 E1012 检查
   （`rt_ck_add/sub/mul`），解释器同样按 int64 报错；`--no-int-ck` 关闭检查后
   溢出按补码回绕，**不再报错**（这是显式的、你自己选的降级）。

还有一条属于「已知缺陷」，不是设计选择：`--strict-types` 只覆盖上面三类，
**不做空值分析、不做未初始化检查、不做可达性分析**。`var x` 之后未赋值就使用，
行为由运行时决定。

## 四、为什么不做完整 HM

- 完整 Hindley–Milner 需要全程序推断 + 泛化，而 Impor 的语义定义是**树遍历解释器**，
  运行期值可以自由换类型（`var x = 1` 之后 `x = "s"` 合法）。给这样的语言套 HM，
  要么推翻动态语义，要么做一套与运行期不一致的静态影子语言。
- 折中路线（渐进类型 + `--strict-types`）的代价是：**只有你打开 strict 档，
  标注才是契约**；关着的时候，标注只是给单态化/优化看的提示。这条边界写在
  这里，而不是藏在实现里。

## 五、这张表的复验方式

```
impor check-types . --strict-types                    # 全仓递归（当前 0 warn）
impor build examples/grade.impor --no-int-ck           # 溢出检查关闭（E1012 不再报）
impor run  <溢出样本>                                  # 解释器侧 E1012
```

如果哪天这三条命令的行为与上表不符，那就是缺陷，请开 issue 并附命令输出——
本文件承诺的是**行为**，不是意图。
