01 / 立场

不是另一个脚本，是一条交付链路。

大多数语言先给你一个 REPL，再让你自己想办法把东西交出去。Impor 的顺序相反：先定义交付物，再倒推语法、诊断、编辑器与课程。

交付物很具体：一个双击就能运行的 .exe，不需要目标机器装 Python，不需要解释器随行，也不把运行环境藏进安装脚本。3.2.3 的 C 后端把 AST 转成 C，再交给随包的 TCC，产物约 100 KB。

但“能生成 exe”只是结果。为了让它可维护，3.1 同时补了三件事：写错能在运行前发现、三个后端必须给同一个答案、新人不看源码也能从 12 课进入。这三件事分别落在类型检查、conformance 门禁与教学判题上。

所以这个网站不按“功能列表”组织，而按一条真实链路组织：语言怎么表述，证据怎么产生，流程怎么走，编辑器怎么接，边界在哪里，最后怎么交付。

先能解释，再能编译，最后能交付。这是一门语言的门槛，也是一套工具链的验收顺序。
  1. A

    可读，不靠中文关键字。

    关键字保持英文，代码可以离开中文环境；诊断、文档、命令行与课程用中文。中文是理解层，不是语法层。

  2. B

    可验，不靠口头承诺。

    23/23 三端一致、18/18 体检、12/12 判题、563 项单测的失败数，全部有命令或报告。数字不藏在发布说明里。

  3. C

    可交付，不停在示例。

    从 impor run 到 impor build，再到 VSIX 与桌面镜像，同一条链路覆盖课堂、工具与单文件分发。

IS / 是

一门教学优先、但以交付为终点的语言；一个 Windows x64 工具链；一次把自举编译器放进一致性门禁的工程实验。

ISN'T / 不是

不是 Python 的替代品；不是完整的静态类型系统；也不是一个已经有 async/await 的并发运行时。

02 / 语言 · 3.2.3 内核

先把错误，拦在运行之前。

类型标注是可选的，检查是动真格的。变量、参数、返回值都能写类型；int / float 互通、T? 可空、any 放行，为渐进迁移留出口，而不是给迁移添堵。

3.2.1 把三件真正影响交付的事做进了编译器：带载荷的结果类型、可验证的 async 状态、跨文件可见性。ADT 让 Ok/Err 能携带数据；async 与 C 后端同步语义对齐，状态不再一边 new、一边 done；private 不再只在本文件生效。类型、穷尽性与访问控制在 impor check 与诊断面板同时给出。3.2.3 保留这套语义，不重塑语言。

这让“能跑”与“写对”分开：运行前能发现的问题，不必留到用户双击 exe 的那一刻。

类型地图 / surface

类型不是装饰，是一张可读的地图。

标注可写可不写；写上去，impor check 就按标注检查。它不改变运行时语义，也不把语言变成一套需要先通过类型考试才能运行的系统。渐进迁移，是设计的一部分。

  • 静态检查只覆盖写了标注的位置；没有标注的代码仍按动态语义运行。

03 / 证据 · 实测

三个后端，必须给出同一个答案。

解释器负责语义，C 后端负责独立 exe，imporc 负责自举。3.2.3 把 ADT、async、JSON、正则与 lambda 一起送进一致性比对：解释器与 C 产物的 9 行输出逐行相同。

23/23conformance · source + desktop · 0 失败
>impor conformance --ci

一致性不是一句口号，是一条命令。每个用例会同时在 Python 解释器、C 后端和自举编译器里运行，比较 stdout、退出码与产物字节。路径里带空格或括号也不会再让自举后端失败：runner 会先把用例复制到无空格临时目录。

04 / 流程 · 从源码到 exe

从一行源码，到一枚 exe。

编译不是黑箱。3.2.3 沿用 3.2.1 的流程：每一步的输入、输出和失败信号都写成命令：先解析，再分析，再检查类型，最后才决定交给解释器、Python 还是 C。每一步都能单独停下来。

01 / parse

解析

源码进入 lexer 与 parser，变成 AST。缩进、字符串、注释与中文文本在这里分开处理。

输入 .impor 源码 · 输出 AST · 失败 exit 2
02 / analyze

分析

impor lint 先找未定义变量、未使用变量、未使用导入与死代码。它不替你做类型判断，只把可疑处标出来。

输入 AST · 输出 lint 诊断 · 失败 报告
03 / typecheck

类型检查

可选标注、返回类型、枚举穷尽、同文件访问控制。没有标注的位置按动态语义放行，any / ? 是明确出口。

输入 AST + 标注 · 输出 类型诊断 · 失败 exit 1
04 / lower

后端选择

同一个 AST 可以交给解释器直接执行，也可以转成 Python 源码，或转成 C 再交给 TCC。选择不同，产物不同。

输出 解释执行 / .py / .c
05 / link

链接

C 后端把 AST 与运行时拼成独立可执行文件。TCC 随包提供，目标机器不需要 Python，也不需要编译器。

输出 约 100 KB exe · 依赖 无 Python
06 / verify

验证

构建不是结束。conformance 比三端，doctor 比环境，bench --gate 比性能门槛。

门禁 23/23 · 18/18 · 983 ms
四个出口 / outputs

同一份源码，四种交付方式。

不是所有人都需要 exe。调试要快，教学要能看见中间产物，分发要不依赖环境。四个出口对应四种真实场景。

impor run解释器直接执行。启动快，适合课堂演示与迭代；不产出独立文件。
impor compile hello.impor -o hello.py转成 Python 源码。中间产物可读、可检查，适合排查转译问题。
impor build -o app.exeC 后端 + TCC，生成独立 exe。约 100 KB，目标机器不需要 Python。
imporc用 Impor 自身写成的自举编译器，原生 C 产物；参与同一套 conformance 门禁。

05 / 诊断 · 错误码

错误码，不是标签，是下一步动作。

3.2.3 的诊断分三层：语法 / 文件、类型 / 访问、运行时。每一条都带位置、原因与修法，而不是只说“出错了”。错误提示是产品的一部分。

layer 01语法 / 文件

解析失败、文件不存在、缩进不合法。退出码 2，先修结构再谈语义。

layer 02类型 / 访问

type-mismatch、return-type、match-exhaustive、access-private。退出码 1。

layer 03运行时

AccessError、E1001、插件 PermissionError。能定位到成员名、行号或权限入口。

诊断层触发下一步
type-mismatch类型声明是 int，值是 str；不做隐式转换。改值，或改声明；不要用 any 掩盖它。
return-type类型函数写着返回 str，实际 return 了 int。对齐返回值，或改返回类型；两者只能改一个。
match-exhaustive类型枚举少写分支，且没有 else / default / 绑定通配。补 case Color.BLUE:，或加 _ 兜底。
access-private类型同文件里，类外直接读 private 字段。调用公开方法；不要把私有字段包成新的公开字段。
access-protected类型同文件里，非子类读取 protected 字段。在子类中使用，或提供受控的公开入口。
AccessError运行时跨文件或绕过静态检查，直接读私有成员。改用方法；静态检查只覆盖同文件，运行时仍会拦。
E1001运行时除零。除数是 0 或空值路径。impor explain E1001 查看原因、修复与示例。
PermissionError编辑器插件写文件，但未授权或路径越出工作区。加 plugin_write_allow，或设置 IMPOR_PLUGIN_PERMISSIONS=write。
pkg auditCI缺 lock、缺 sha256、明文 HTTP 源、requires 缺失。补 lock 与哈希，换 HTTPS 源，补齐依赖声明。
>impor explain E1001

不道歉，也不含糊。说清哪里错、为什么错、怎么修。错误提示不是情绪，是定位工具。它应该让人少开一次搜索，多改对一个地方。

3.2.3 增量 / editor

这一版只做编辑器，五项都接上真实运行路径。

不是把旧静态近似换个标题，而是把覆盖率、插件面板、索引、搜索、UIA 与 Quick Fix 都改成可运行的闭环，并用 GUI 与跨进程用例逐项验证。

运行时覆盖率

解释器逐语句命中，不再猜“测试有没有引用函数”。

解释器按 lineno 累加命中，AST 语句行做分母；视图给出“行 / 命中 / 状态 / 源码”，双击跳转，可运行、清空、重算。

跨进程面板

builder 在子进程里跑，控件树交父进程渲染。

Frame / Label / Button / Entry / Text / Checkbutton / Treeview 被序列化成 UI 描述；动作按 act_N 回调子进程，不再跨进程传 Tk 对象。

后台索引

启动和切工作区不再被全量扫描卡住。

refresh_index_async 用代次合并请求；ProjectIndex 加可重入锁，刷新与定义、引用、补全、重命名并发时仍拿到一致结果。

搜索可取消

扫描到一半可以停，已扫结果保留。

后台线程按 should_cancel 逐文件检查；“取消 / 加载更多”按钮与滚动续接共用 token，过期结果不会覆盖新搜索。

逐控件 UIA

16 个 provider，角色、状态、快捷键、边界都可读。

控件树按 group 分组，Control+Tab 循环焦点，Enter 执行；同时导出 control_providers.json，外部工具可按稳定 id 枚举。

3.2.3 同时扩面：Quick Fix 覆盖关键字拼写、条件误用 =、括号/引号/大括号未闭合诊断知识库补 return / 穷尽 match / 重复定义 / 类型不匹配 / async / ADT 载荷 / FFI批量修复加入 undo 分隔
3.2.1 底座：UIA 语义桥接（原生 EDIT）设置同步（newer/local/remote）插件独立进程隔离命令/格式化器/主题 RPC写权限仍由父进程校验

符号跳转 / 重命名跳转到定义、查找引用、安全重命名；重构入口与索引共用。动态派发与字符串引用无法完全静态解析。

插件面板插件在隔离进程执行 builder，父进程按 UI 描述渲染控件；按钮通过 panel_action 回调子进程。控件上限 240 个、层级 8 层；只支持已列出的控件类型。

DAP 调试断点、条件断点、日志点、单步与调用栈；调试 UI 在编辑器内。窗口级验证需人工打开；没有自动化 GUI 测试。
测试浏览器运行测试、查看失败与统一 diff；适合表驱动用例。依赖项目自身的测试入口。

项目骨架 / impor.toml

依赖不是口头声明，是一份可锁定的清单。

impor pkg init 生成项目骨架：入口、模块搜索路径、依赖与私有源都写进 impor.toml。锁文件负责复现，audit 负责在 CI 里拦住缺哈希与明文 HTTP。

impor.toml / 由 pkg init 生成project manifest
[project]
name = "impor_pkg"
version = "0.1.0"
entry = "main.impor"
sandbox_default = false

# 模块搜索路径（相对项目根）
[module_search_paths]
paths = ["./lib"]

# 依赖声明；锁文件负责复现
[dependencies]

init 建骨架，install 拉依赖，lock 固定版本与哈希，graph 打印树，audit 把错误变成退出码 1。私有源令牌只从环境变量读取，不写进仓库。

课程结构 / 4 arcs

12 课不是 12 个孤立的例子。

课程按四条弧线推进：先能输出与计算，再处理数据与文本，然后进入对象与枚举，最后用异常和闭包收口。

01–04语法与流程

输出、变量、条件、循环。目标是写出一段能读懂的成绩分级。

05–08数据与文本

数组、函数、字符串、字典。开始处理一批数据，而不是一个值。

09–10对象与枚举

类、构造、方法、枚举与 match 穷尽。结构开始承担语义。

11–12异常与闭包

抛出、捕获、收尾；内层函数捕获外层状态。抽象开始闭合。

08 / 变更 · 3.2.3

改了什么，没改什么。

3.2.3 在 3.2.1 的语言与安全底座上，把编辑器的五件事做成闭环：运行时行覆盖率、插件面板跨进程 builder、索引与搜索后台化、UIA 逐控件 provider、诊断 Quick Fix 扩面。语言、三端与安全策略保持 3.2.1 的结论，不重复宣称。增量要写清楚，遗留也要写清楚。

编辑器面补的是“编辑器自己可验证”：覆盖率不再用静态引用近似，插件面板不再是一个占位面板，索引不在启动时阻塞主线程，搜索可以中途取消并保留已扫结果，UIA 从整窗语义树细化到 16 个可执行控件。

诊断面补的是“Quick Fix 扩面”：关键字拼写、未声明变量、条件 =、括号/引号/大括号补齐、未使用变量；解释窗口改为“原文 / 为什么 / 怎么修 / 最小示例”，标题带错误码。

版本不是数字变大，是下一件事变得可做。3.2.3 让编辑器五项都能在同一份代码上跑通；真正的并发搜索、OS 级沙箱与代码签名仍留给下一版。

09 / 场景 · 三条链路

课堂、工具、CI，各走一条。

同一门语言，三种使用方式，不需要三套入口。下面三条链路都用 3.2.3 的真实命令，失败信号也一致：退出码、诊断码、门禁结果。

01 / classroom

课堂：从讲义到判题。

老师先写出一课，学生拿到练习，最后用同一条命令判题。讲与练不脱节。

$ impor teach 3 --write $ impor teach grade 3 lesson03_answer.impor
适合：课堂教学 · 自学者 · 12 课完整路径
02 / tool

工具：从脚本到 exe。

先建模板，格式化，跑通，再交给 C 后端。产物是单文件，不把 Python 带到目标机器。

$ impor new tool --template script $ impor fmt tool.impor $ impor build tool.impor -o tool.exe
适合：桌面小工具 · 数据处理 · 离线分发
03 / ci

CI：从检查到门禁。

类型、三端一致、依赖审计、性能门槛，四条命令四个退出码；失败就停，不靠人盯输出。

$ impor check main.impor $ impor conformance --ci $ impor pkg audit $ impor bench --gate
适合：提交前 · 发布前 · 桌面镜像验收
同一条链路：没有“演示模式”和“真实模式”两套命令。课堂上跑通的判题，和 CI 里跑的门禁，是同一套实现。
10 / 边界 · 还没做的（3.2.3 残留）

没做完的，也摆在这里。

把边界写清楚，是工程的一部分，不是页脚的免责声明。3.2.3 不是终点，下面这些是明确遗留，而不是“以后再说”。

“能交付”不等于“什么都会”。不把未完成项说成已完成，也不把历史用例的失败藏起来。你看到的每个数字，都有对应的命令或报告。

  • —
    自举子集　imporc 仍不支持带载荷 ADT、async/await、lambda、JSON、正则；版本号 3.2.3 但明确输出“子集模式”。
  • —
    真正的并发　async 目前是单线程即时求值，没有事件循环、抢占或并行；需要并发时应等任务调度器。
  • —
    C 后端 FFI　FFI 只在解释器可用；编译产物调用会报未定义。这是刻意保留的边界。
  • —
    OS 级沙箱　安全策略是应用层：路径围栏、原子写、审计、默认拒绝；插件写/网络/子进程由 audit hook 强制，但未启用 AppContainer / Job Object，ctypes 原生调用仍可绕过。
  • —
    发布物签名　更新通道只有 HTTPS 与 SHA256 清单，没有代码签名；安装前仍应自行核对哈希。
  • —
    编辑器长尾　覆盖率是静态调用近似，不是运行时行覆盖；UIA 是 Treeview 语义映射，不是逐控件 provider；搜索只有滚动加载，没有“加载更多”按钮。
  • —
    全量 unittest　563 项里仍有历史中文关键字与旧夹具导致的失败；3.2.3 新增能力用定向用例、GUI 冒烟与 conformance 验证，不宣称全绿。
  • —
    GUI 自动化　编辑器只做代码级与单元级验证；窗口级行为需人工打开确认，没有自动化 GUI 测试。

11 / FAQ · 十二个问题

先把最容易误解的说清楚。

下面这些问题来自真实使用与版本说明。答案尽量短，但不回避边界；能在命令行验证的，都给出命令。

01中文关键字还能用吗？
不能作为 3.2.3 的主路径。关键字保持英文，中文留在诊断、文档、12 课与命令行输出里。旧版中文语法不再作为卖点；历史中文关键字用例仍有失败，已在边界页列出。
023.1 是一次重写吗？
不是。它站在 7.2 的编辑器底座上，增量集中在类型检查、三端门禁、项目质量检查、教学入口与依赖审计。既有能力没有被推翻，只是被接进同一条可验证链路。
03它和 Python 是什么关系？
不是替代关系。Python 的生态、库与并发能力远大于 Impor；Impor 的约束更窄：独立 exe、三端一致、12 课可判题、单文件自包含。选它，是选一条更小但更可控的交付链路。
04生成 exe 需要目标机器装 Python 吗？
不需要。C 后端把 AST 与运行时编成独立可执行文件，TCC 随完整包提供。打包机需要 TCC；目标机器只需要 Windows x64。产物约 100 KB。
05为什么首次构建写了 0.66 s，也写了 0.81 s？
这是不同轮次的实测区间，不是四舍五入。文档记录 0.66 s（转译 0.07 s、TCC 0.24 s），站内旧文记录 0.81 s。缓存命中后是 0.05 s，第三次 0.03–0.04 s；--no-cache 可强制全量。
0623 项 conformance 够证明什么？
证明现有用例下，解释器、C 后端与 imporc 的输出与退出码一致；不证明所有语义都已覆盖。带载荷 ADT、async、跨后端 JSON / 正则 / lambda 不在门禁内，不能拿 23/23 代替完整正确性。
07doctor 18/18 是什么？
14 个模块、3 个自举产物与随包 TCC 的可用性检查。它证明环境能跑，不证明每个功能都对；功能正确性由定向测试、conformance 与教学判题分别覆盖。
0812 课怎么判题？
impor teach 3 --write 写出练习与答案；impor teach grade 3 lesson03_answer.impor 运行文件并与期望输出比对。判题看输出，不看代码是否长得像标准答案。
09pkg audit 会拦住什么？
缺 lock、缺 sha256、明文 HTTP 源、requires 缺失。错误退出 1，只有警告退出 0。pkg graph 从 lock 打印依赖树，并标记循环与未安装项。
10编辑器插件能直接写文件吗？
默认拒绝。需要 plugin_write_allow 或 IMPOR_PLUGIN_PERMISSIONS=write 授权；路径用 commonpath 限制在工作区，越界抛 PermissionError。
11跨文件私有访问能静态拦住吗？
不能。静态访问控制只覆盖同一文件；跨文件或绕过静态检查时，运行时仍会抛 AccessError。这是当前明确的边界。
12下一步做什么？
带载荷 ADT、async/await、C 后端与自举的 JSON / 正则 / lambda、跨文件静态访问、编辑器长尾。按版本推进；没做之前，不会写成“即将支持”。
